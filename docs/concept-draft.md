# The Last Ship — 게임 기획서

> 상태: 피벗 정본 v0.1 · 갱신 2026-08-03 · 프로젝트 저장소명 `Project-DoodleUp`과 코드 식별자 `LastShift*`는 당분간 유지
>
> **⚠ 진행 구조 정정 (`2026-08-10`).** 현재 게임명은 **The Last Ship**이고, 도킹 중심 목표는 폐기됐다. 이 문서의 협동 약속·상태 기반 사고·상황 코미디는 유지하지만, 도킹 목표·도킹 성공 조건·도킹 결과는 `docking-removal-persistent-ship-save-v1.md`가 대체한다. 현재 진행의 본체는 **함선/거점/자원 누적과 세이브/이어하기**다.

## 1. 한 줄 정의

**승무원의 위치, 선내 물건 배치, 기존 손상과 과잉 대응이 다음 사고를 만들고, 1~4명이 짧은 물리 협동으로 그 연쇄를 되돌리는 우주선 생환 시뮬레이션.**

| 항목 | 방향 |
|---|---|
| 장르 | 1~4인 협동 생환 시뮬레이션 / 물리 상황 코미디 |
| 플랫폼 | Steam PC 우선 |
| 엔진 | Unity 6000.4.0f1 |
| 시점 | 3D 캐릭터 직접 조작 |
| 세션 | 짧은 항해 단위. 정확한 길이는 P0 이후 결정 |
| 고정 구조 | 출항 → 항해 → 생환 결과 |
| 변동 구조 | 외부 자극, 선내 상태, 대응, 사고 연쇄, 생환 방식 |
| 핵심 감정 | “각자 일했다”가 아니라 “우리가 같이 이 난장판을 살렸다” |

## 2. 플레이 약속

1. **같은 사건도 같은 시나리오로 진행되지 않는다.** 운석 충돌은 고정 이벤트 체인을 실행하는 카드가 아니라 현재 우주선에 충격 위치·방향·세기를 투입하는 자극이다.
2. **내 행동이 1초 안에 동료의 상황을 바꾼다.** 전력 전환, 급선회, 감압, 점화가 동료의 화면·몸·작업 환경에 즉시 나타난다.
3. **수리는 반복 업무가 아니라 짧은 공동 수습이다.** 붙잡기, 전달, 동시 조작, 타이밍 맞추기가 중심이다.
4. **실수는 대부분 회복 가능하다.** 작은 실수와 과잉 대응은 즉사보다 웃긴 추가 문제를 만든다.
5. **한 항해는 고유한 생환 이야기로 남는다.** 결과 화면은 점수보다 실제 원인과 대응의 사슬을 보여준다.
6. **정보는 구역에 귀속된다.** 각 구역은 자기 상태를 가장 정확히 보여주고, 다른 구역에는 소리·진동·출력 저하 같은 결과만 전달한다. 대화가 가장 빠른 정보 전달 수단이어야 한다.
7. **생환에는 절충이 있다.** 모든 기능을 원상복구하는 것만 정답이 아니다. 추진·산소·화물·목적지 중 일부를 포기하고 살아 돌아오는 선택이 가능해야 한다.

## 3. 코어 루프

```text
이상 징후 발견
→ 상황을 말로 공유하고 우선순위 결정
→ 사람·물건·전력을 재배치
→ 2~3개의 짧은 행동을 함께 수행
→ 우주선 상태가 실제로 변화
→ 해결 또는 과잉 대응이 새로운 조건 생성
→ 목적지를 유지하거나 생환 방법 변경
```

- 한 수습 박자는 대략 **20~40초**를 목표로 한다.
- 모든 수습 행동은 다른 플레이어의 선택지를 최소 하나 열거나 닫아야 한다.
- 사건 하나를 완전히 닫은 뒤 다음 카드를 뽑는 구조가 아니다.
- 이전 손상과 배치가 남아 다음 자극의 결과를 바꾼다.
- 상태는 `정상 → 불안정 → 고장 → 위기`로 악화한다. 첫 실수는 다음 수습을 만들고, 누적된 방치와 과잉 대응이 생환 실패를 만든다.
- 항해 종료는 정상 도착, 비상 도킹, 구조선 인계, 구명정 탈출처럼 여러 형태가 가능하다.

## 4. 상태 기반 사고 시뮬레이션

### 4.1 핵심 상태

P0에서는 다음 다섯 계통만 사용한다.

| 계통 | 대표 상태 | 다른 계통에 미치는 영향 |
|---|---|---|
| 추진 | 출력, 연료, 엔진 상태 | 전력·열·선체 진동·항로 |
| 전력 | 생산량, 배전, 케이블 연결 | 추진·산소·문·조명·방어 장치 |
| 산소 | 압력, 저장량, 공급 상태 | 승무원 활동·감압·외부 작업 |
| 선체 | 구역별 내구, 파공, 문 상태 | 산소·물건 이동·외부 접근 |
| 열 | 설비별 온도, 냉각 상태 | 출력 제한·화재·산소 소비 |

상태는 전역 숫자 하나가 아니라 가능한 범위에서 **구역·설비·물건에 귀속**한다. 같은 선체 손상도 어디에 생겼는지가 중요하다.

### 4.2 외부 자극

외부 자극은 결과를 지정하지 않고 시뮬레이션에 입력값을 준다.

- 운석: 충돌 위치·방향·충격량
- 태양풍: 노출 면·지속 시간·전력 교란량
- 조난선: 위치·요구·보유 자원·잠재 위험
- 우주 생물: 접근 위치·관심 대상·행동 성향
- 항로 이상: 필요한 추진·조향·시간 압박

### 4.3 결과 계산 원칙

```text
결과 = 외부 자극
     × 현재 계통 상태
     × 기존 손상
     × 승무원 위치
     × 물건 배치·고정 상태
     × 플레이어 대응 시점과 강도
```

고정된 `운석→선체 균열→외부 수리` 스크립트를 두지 않는다. 상태 임계치를 넘은 실제 설비와 구역이 문제를 발생시킨다.

### 4.4 사건 노드 규격

콘텐츠 사건은 다음 항목만 정의한다.

1. 발동 가능한 환경과 상태 범위
2. 예고 신호와 관찰 가능한 증상
3. 물리적 자극 또는 상태 변화
4. 즉시 선택 가능한 대응
5. 대응의 비용과 부작용
6. 회복 경로 최소 2개
7. 악화 조건과 생환 방식 변화

가능한 해결은 단일 정답 대신 최소한 다음 세 계열을 허용한다.

- **안전 복구:** 느리지만 후유증이 적다.
- **빠른 우회:** 즉시 기능을 살리지만 다른 계통에 부담이나 임시 손상을 남긴다.
- **성능 포기:** 기능·화물·목적지 일부를 포기하고 생환 최저선을 확보한다.

**고정 후속 사건 목록은 정의하지 않는다.** 후속 문제는 변화한 상태를 읽은 계통 규칙이 발생시킨다.

## 5. 동일 자극의 변주 기준

동일한 좌현 운석 충돌도 다음처럼 달라져야 한다.

### 상황 A — 고열·고추력

- 높은 추력과 엔진 열 상태에서 충격이 냉각 결합부를 이탈시킨다.
- 한 명이 자세와 추력을 낮춰 열 상승을 늦추는 동안 다른 한 명이 호스를 붙잡고 냉각통을 연결한다.
- 빠른 우회를 선택하면 추력은 회복하지만 도킹까지 열 제한이 남는다.

### 상황 B — 전력 과부하·느슨한 배터리

- 충격으로 배터리가 통로를 굴러 bus 연결을 끊고 조향과 산소 펌프를 함께 약화한다.
- 한 명은 관성 자세를 유지하고, 다른 한 명은 배터리를 붙잡아 고정하거나 산소를 끄고 조향만 임시 복구한다.
- 성급한 점화는 배터리와 승무원을 다시 날려 보낼 수 있다.

### 상황 C — 나쁜 자세·고압 산소

- 약한 측면이 충격을 받아 산소관과 선체 결합부에 누출이 생긴다.
- 한 명이 감압 방향과 문을 제어하고 다른 한 명이 날아가는 patch plate를 붙잡아 양쪽 latch를 맞춘다.
- 엔진 출력을 포기하면 재가압 전력을 확보할 수 있지만 도킹 성능이 낮아진다.

**합격 조건:** 세 상황이 모두 수리 키트 왕복이나 동일 게이지 채우기로 수렴하지 않고 서로 다른 대화·위치·물건·타이밍 협동을 요구한다.

## 6. 협동의 문법

### 6.1 직접 상호 영향

- 조종사의 급선회가 동료와 물건을 움직인다.
- 기관실의 배전이 동료가 있는 방의 문·조명·산소를 바꾼다.
- 감압과 재가압이 물건 전달 경로와 외부 작업을 바꾼다.
- 엔진 점화가 외부 작업자의 안전줄과 몸에 힘을 가한다.

UI 알림만 변하는 것은 협동으로 인정하지 않는다.

### 6.2 공동 행동 어휘

- 흔들리는 설비를 **붙잡아 주기**
- 케이블·산소통·공구를 **직접 전달하거나 던지기**
- 무거운 부품을 **함께 들기**
- 떨어진 동료를 **끌거나 안전줄로 회수하기**
- 두 위치에서 **동시에 조작하기**
- 짧게 공급되는 전력에 맞춰 **타이밍 행동하기**
- 하나의 계통을 살리기 위해 다른 계통을 **함께 포기하기**

동시 조작은 유일한 정답이 아니라 **빠르고 안전한 지름길**이다. 1인은 임시 고정과 마지막 조종 입력 유지로 순차 해결할 수 있고, 2인 이상은 한 명이 붙잡는 동안 다른 사람이 연결해 시간과 위험을 줄인다.

### 6.3 역할 교대

직업과 전용 능력은 P0에 두지 않는다. 현재 위치, 가진 물건, 남은 인원 때문에 역할이 바뀌어야 한다. 인원이 늘어도 각자 한 설비 앞에 상주하는 구조는 실패다.

## 7. 노동감을 막는 금지 규칙

다음은 코어 행동으로 사용하지 않는다.

- 같은 버튼을 오래 누르거나 같은 입력을 반복해 게이지 채우기
- 경고 아이콘이 정답 도구와 위치를 모두 알려주는 수리
- 시간을 채우기 위한 수리 키트·탄약 장거리 왕복
- 한 사람이 한 방에서 계기판만 감시하기
- 역할별 독립 미니게임을 동시에 수행하기
- 사건 종류 추가만으로 반복성을 해결하기
- 해결 불가능한 랜덤 조합

운반은 거리가 아니라 **누가 무엇을 들고 있어 다른 행동을 못 하는지**, **어떤 경로로 전달할지**, **우주선 움직임이 물건을 어디로 보내는지**를 만들어야 한다.

## 8. 물리 상황 코미디

웃긴 장면은 개그 이벤트를 별도로 추첨해서 만들지 않는다.

```text
선의의 협동 행동
+ 불완전한 타이밍 또는 과잉 대응
+ 읽을 수 있는 물리 반응
+ 즉시 시도 가능한 복구
= 공유할 수 있는 웃긴 사고
```

예시:

- 던진 렌치가 비상 버튼을 누른다.
- 산소통을 굴렸는데 급선회로 보낸 사람에게 돌아온다.
- 엔진을 너무 일찍 점화해 붙잡고 있던 동료가 통로 끝까지 날아간다.
- 작은 화재를 끄려고 구역 전체를 감압해 공구까지 우주로 날린다.
- 두 사람이 같은 배터리를 반대 방향으로 끌다가 문에 낀다.

### 코미디 안전 규칙

- 첫 실수는 대부분 복구 가능해야 한다.
- 원인과 물리 반응이 화면에서 보여야 한다.
- 실수 직후 할 수 있는 행동이 있어야 한다.
- 반복된 방치나 큰 희생 선택만 생환 실패로 이어진다.
- 조작 불편, 긴 재작업, 무작위 즉사는 코미디로 간주하지 않는다.

## 9. 1~4인 스케일링

| 인원 | 동시 핵심 작업 | 지속 점유 | 보완 방식 |
|---|---:|---:|---|
| 1인 | 최대 1개 | 없음 | 임시 클램프·짧은 자동 유지·긴 예고. 해결은 직접 수행 |
| 2인 | 최대 2개 | 최대 1개 | 붙잡기+조작, 전달+타이밍의 기본형 |
| 3인 | 최대 3개 | 최대 1개 | 두 명 수습+한 명 운항/물자 지원 후 역할 교대 |
| 4인 | 최대 3~4개 | 최대 2개 | 두 팀이 나뉘되 전력·물건·공간을 공유해 서로 영향 |

스케일링은 체력 배수가 아니라 다음을 조절한다.

- 동시에 악화되는 계통 수
- 임시 유지 장치의 지속 시간
- 두 사람이 필요한 물건과 조작 수
- 사건 예고 시간
- 구역 간 이동과 전달 경로
- 회복 경로의 수

P0는 솔로에서 인과 가독성과 soft-lock 부재만 확인하고 **2인 협동 코어**를 재미 판정의 기준으로 삼는다. 솔로는 마지막 조종 입력을 약 8초 유지해 순차 해결할 수 있지만, 솔로 PASS를 협동 재미 PASS로 간주하지 않는다.

3인 확장은 2인 세 변주 PASS 뒤에만 연다. 세 번째 사람이 대기나 속도 보조가 아니라 운반·고정·교차 확인으로 결과를 바꿔야 한다. 4인 확장은 3인 PASS 뒤에만 열며, 네 번째 사람이 물건 간섭·동시 구조·대안 경로를 만들고 매 항해 역할 교환이 발생해야 한다. 실패하면 최대 인원을 2~3인으로 낮춘다.

## 10. 항해와 생환

### 출항

- 목적지와 예상 항해 조건
- 초기 자원과 선내 물건 배치
- 잠재 결함과 기존 손상
- 조우 가능한 외부 대상

### 항해

- 외부 자극과 현재 상태가 결합한다.
- 플레이어 대응이 계통과 배치를 바꾼다.
- 손상과 임시 수리는 항해 동안 남는다.
- 정상 목적지를 포기하고 더 안전한 생환 방식을 택할 수 있다.

### 생환

- 예정 목적지 정상 도착
- 파손 상태로 비상 도킹
- 외부 우주선에 구조
- 가까운 정거장으로 목적지 변경
- 구명정 탈출

생환은 이분법적 승패보다 **무엇을 보존하고 무엇을 희생했는지**를 보여준다.

## 11. 결과 카드

```text
좌현 운석 충돌
→ 느슨한 배터리가 발전기 케이블 분리
→ 두 승무원이 배터리를 붙잡는 동안 조향 전력 단속 공급
→ 성급한 점화로 공구함이 산소 밸브 파손
→ 화물칸을 포기하고 비상 정거장 생환
```

기록 항목:

- 생환 방식과 생존 승무원
- 남은 추진·전력·산소·선체·열 상태
- 포기한 화물과 구역
- 임시 수리와 과잉 대응 횟수
- 동료 또는 물건을 날려 보낸 횟수
- 가장 긴 실제 인과 사슬
- 항해 칭호

## 12. 경쟁작 경계

- `Barotrauma`: 상태 전파는 참고하되 호러·장시간·전문 역할·고복잡도를 따라가지 않는다.
- `Void Crew`: 명료한 역할 어휘는 참고하되 전투와 반복 보급을 중심에 두지 않는다.
- `Lovers in a Dangerous Spacetime`: 즉각적 상호의존과 역할 이동을 참고한다.
- `Heavenly Bodies`: 보이는 물리 실수와 회복성을 참고하되 조작 피로를 답습하지 않는다.
- `Fueled Up`·`Catastronauts`: 경고→지정 도구→게이지 채우기의 작업 청소 구조를 피한다.

차별점은 `우주선 안에서 수리한다`가 아니라 **현재 상태와 물건 배치가 매번 다른 협동 수습을 생성한다**는 점이다.

## 13. 역사적 P0 검증 범위 (대체됨)

> 아래 범위는 초기 물리 협동을 검증한 프로토타입 기록이다. 수동 도킹 목표와 성공 조건은 현재 게임의 진행 구조로 사용하지 않는다.

P0는 완성된 항해가 아니라 **예고된 운석을 맞고 5~7분 안에 추진을 복구해 수동 도킹하는 항해 하나**로 코어 주장을 검증한다. 20초 사전 경고 동안 회피·감속·계속 가속을 선택하고, 충돌 또는 근접 충격 이후 생환 최저선까지 복구한다. 성공 기준은 무손상이 아니라 `추력 30% 이상, 산소 20% 이상으로 도킹`이다.

> **같은 운석 자극이 서로 다른 선내 상태에서 세 가지 다른 사고와 협동 행동을 만들고, 그 수습이 노동보다 협동과 웃음으로 느껴지는가?**

필수:

- 작은 우주선 회색박스 3구역
- 2명 로컬 캐릭터 또는 빠른 2인 입력 구성
- 추진·전력·산소·선체·열의 최소 상태
- 위치와 고정 상태가 유지되는 배터리·냉각통+호스·patch plate·다목적 손잡이/tether 각 1개
- 운석 자극 1종
- 사전 상태 프리셋 3종
- 붙잡기·전달·연결·동시 조작·점화 타이밍
- 회복 가능한 물리 실수
- 원인 사슬을 보여주는 간단한 결과 요약

명시적 제외:

- 온라인·매칭·캠페인·메타 성장
- 전투·포탑·적 AI·다수 외계 종족
- 절차 생성 우주와 다수 이벤트 덱
- 완성 아트·캐릭터 커스터마이즈·대사극
- 현실 궤도 물리와 복잡한 부품 시뮬레이션
- 3~4인 구현과 인원별 추가 콘텐츠
- EVA, 제작·인벤토리, 연료 경제, AI 승무원
- 출시 수준 QA·텔레메트리·증거팩

## 14. 사용자 플레이 판정

P0는 사용자가 직접 플레이해 판단한다.

통과 질문:

1. 동료에게 자발적으로 명령·경고·도움을 요청했는가?
2. 내 행동이 1초 안에 동료의 상황을 바꿨는가?
3. 세 프리셋이 서로 다른 대화와 협동 행동을 만들었는가?
4. 실수가 짜증이나 즉사보다 웃음과 추가 수습으로 이어졌는가?
5. 수습 뒤 “게이지를 채웠다”가 아니라 “우리가 살렸다”고 느꼈는가?
6. 다시 한다면 충돌 전에 무엇을 다르게 배치·고정·차단할 것인가?
7. 깨끗한 성공과 간신히 수습한 성공 중 어느 쪽을 다시 하고 싶은가?

탈락 조건:

- 세 프리셋이 동일한 도구 왕복과 동일 수리 동작으로 수렴
- 20초 이상 한 사람이 반복 입력 또는 대기
- 각자 독립된 설비만 만지고 상호 영향이 체감되지 않음
- 작은 실수가 즉사·긴 재작업·조작 불쾌감으로 이어짐
- 사고 원인을 랜덤 탓으로만 이해함
- 플레이 후 바꾸고 싶은 대응이나 재도전 의사가 없음
