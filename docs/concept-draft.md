# DOODLE UP (가칭) — 컨셉 초안

> 상태: 초안 (기획서 아님) · 작성 2026-07-31 · 결정된 것과 미결인 것을 구분해 적음

---

## 1. 한 줄 요약

**손이 닿는 곳에 펜으로 발판을 그려 끝없이 위로 올라가는 1~4인 코옵 등반 게임.** 그린 것은 실물이라 모두에게 적용되고, 잉크 게이지가 한정돼 있어 뒤를 지워야 앞을 그릴 수 있다.

| 항목 | 값 |
|---|---|
| 장르 | 프렌드슬롭 (소셜 코옵 파티) / 물리 등반 |
| 인원 | 1~4명 |
| 플랫폼 | Steam PC (마우스+키보드 전제) |
| 엔진 | Unity 6000.4.0f1 |
| 시점 | 3D · 탑을 도는 궤도 카메라 |
| 드로잉 | **캐릭터 손이 원점. 팔이 닿는 범위 안에만 그린다** |
| 톤 | 우스꽝스럽지만 귀여운 캐릭터 / 아기자기하고 예쁜 맵 |
| 런 길이 | 미정 (프로토타입 후 결정) |

## 2. 코어 루프

```
    손 닿는 곳에 그린다  →  그 위로 오른다  →  뒤를 지운다  →  잉크 회복  →  다시 그린다
           ↑                                                                    │
           └────────────────────────────────────────────────────────────────────┘
```

**그리기와 오르기는 별개의 모드가 아니라 하나의 동사다.** 사거리가 팔 길이이므로 스트로크는 짧고 잦다. 긴 구조물을 설계하는 게 아니라 *한 걸음 앞을 만드는* 동작이다. 그리며 오른다.

잉크 게이지가 **동시에 존재할 수 있는 잉크의 상한**이므로, 뒤를 정리하지 않으면 앞을 그릴 수 없다. 전진은 선택이 아니라 강제된다.

## 3. 펜 규칙 (핵심)

### 3.1 사거리 — 손이 원점이다

- 스트로크는 **캐릭터의 손 위치에서 시작**한다
- 그릴 수 있는 범위는 **팔이 닿는 거리 + 잉크가 허용하는 길이**
- 손이 닿지 않는 곳에는 그릴 수 없다

> **이 규칙 하나가 세 문제를 동시에 푼다.** ①마우스로 3D 깊이를 지정하는 문제 (손이 실제 3D 기준점이므로 깊이가 결정 사항에서 빠진다) ②정밀도 문제 (손 주변만 그리니 화면상 배율이 크고 기준점이 눈에 보인다) ③그리기와 오르기의 리듬 충돌 (스트로크가 짧아 정지가 사라진다)

### 3.2 잉크 게이지

- 게이지는 **누적 소비량이 아니라 현재 존재하는 잉크의 총량**이다
- 한 번에 게이지만큼만 그릴 수 있다
- **취소·지우기 시 잉크가 즉시 환급**되어 다시 그릴 수 있다
- 시간에 따른 자연 회복 없음. 충전소·리필 아이템 없음 — **지우기가 유일한 회복 수단**
- 잉크 소비량 = **스트로크 길이** (두께 고정이므로 길이만 변수)

> 취소가 무료라는 점이 정밀도 스트레스를 크게 낮춘다. 틀리게 그려도 손해가 0이다.

### 3.3 앵커 규칙

- 그린 것은 **질량이 있는 물리 오브젝트**다
- **지형에 닿게 그리면 고정**된다
- **공중에 그리면 떨어진다**
- 한쪽 끝만 지형에 닿으면 → 매달린 로프·진자처럼 거동

> 게임의 실력이 *"어디에 앵커할 수 있는지 읽는 눈"* 으로 정의된다. **레벨 디자인 = 앵커 포인트 배치.**

### 3.4 두께

- 스트로크 두께는 **고정**. 플레이어가 조절하지 않음
- 기준: **캐릭터가 한 발로 밟을 수 있는 굵기**
  - 캐릭터 키를 `1.0` 유닛으로 잡으면 발 폭 ≈ `0.15~0.20`
  - 스트로크 캡슐 반지름 **`0.12~0.15`** 에서 시작해 손으로 조정
- 두께가 두꺼운 것이 정밀도 요구를 낮추는 효과도 있다

> 두께를 가변으로 만들면 잉크 경제가 2변수가 되어 게이지가 읽히지 않고, 얇게 그려 잉크를 아끼는 치사한 최적해가 생긴다. v1은 고정.

### 3.5 펜의 용도 — 게임이 정하지 않는다

| 형태 · 앵커 | 결과 |
|---|---|
| 지형 두 점을 잇는 선 | 발판 / 다리 |
| 머리 위 지형에 붙인 판 | 방패 (날아오는 물체 막기) |
| 비스듬한 선 | 램프 (자기 사출) |
| 한쪽만 앵커한 긴 선 | 로프 · 진자 |
| 앵커 위에 얹은 막대 | 시소 (친구 발사) |
| 공중에 그린 덩어리 | 추 (떨어지며 스위치 누름) |
| 추락 지점 아래 그물 | 친구 구조 |

**동작 선택 버튼은 만들지 않는다.** 형태와 앵커 여부만으로 물리가 결정한다. 우리가 예상하지 못한 8번째 용도가 나오면 성공한 설계다.

**표현력은 마우스에서 몸으로 이전된다.** 사거리 제한 때문에 *어디서 그리느냐*가 새로운 표현 축이 된다 — 점프 중에 그리기, 매달려서 그리기, 친구가 발사해준 상태에서 그리기.

## 4. 원거리 확장 — 펜촉 화살 (후반 티어)

사거리 제한이 표현력을 줄이므로, 그것을 **획득하는 도구**로 되돌린다.

- 펜촉을 단 화살을 **조준해서 쏜다**
- 화살이 맞은 지점이 **두 번째 앵커**가 된다
- 손 ↔ 화살 지점 사이에 자유곡선으로 그릴 수 있다

> **화살은 무기가 아니라 "캔버스를 원거리에 설치하는 도구"다.** 두 점을 직선으로만 잇게 하면 프리핸드 낙서 감성이 죽고 "선분 잇기"가 되어버린다. 두 앵커로 깊이가 확정된 상태에서 그 사이를 자유롭게 그리게 해야 한다.

**깊이 문제가 재발하지 않는 이유:** 화살이 맞은 지점은 충돌로 확정된 실제 3D 점이다. 플레이어가 깊이를 지정하지 않고 물리가 정한다.

**설계 근거**
- 사거리 확장이 스탯이 아니라 **조준 실력**으로 게이팅된다
- 잉크 비용이 거리에 비례하므로 게이지가 자연스러운 사거리 상한이 된다 (별도 수치 불필요)
- 원거리 용도가 되살아난다: 먼 다리, 원격 방패, **떨어지는 친구를 향해 쏘고 그 사이에 잉크를 걸어 받아내기** ← 게임 대표 순간 후보
- 기본 규칙(팔 길이)을 먼저 몸에 익힌 뒤 예외를 주는 순서여야 한다. 처음부터 주면 안 된다

**주의: 화살이 협력 창발을 잠식할 수 있다.** 원거리가 열리면 §6의 "어깨 태우기"가 죽는다. 화살을 회수해야 하는 소모품으로 두거나(쏜 화살을 주워야 함 → 등반 루프와 엮이고, 친구가 주워 던져줄 수 있어 또 협력이 생긴다) 잉크 비용을 크게 잡아 상시 사용을 막아야 한다.

## 5. 3D 드로잉 입력 — 해결 방식

**문제:** 마우스는 2축, 3D 공간은 3축 → 깊이를 지정할 수 없다. 스무딩·스냅으로 고쳐지는 문제가 아니다. (Tilt Brush가 6DOF VR 컨트롤러를 쓰는 이유)

**해법:** 깊이를 플레이어의 결정에서 **뺀다.**

- 스트로크의 원점은 **캐릭터의 손** — 월드의 실제 3D 점이고, 플레이어는 자기 캐릭터 손 위치를 몸으로 안다
- 마우스는 **방향과 형태만** 담당한다
- 드로잉 평면은 손을 지나는 카메라 수직 평면
- 원거리는 §4의 화살로만 열리고, 그때도 깊이는 충돌이 정한다

**깊이 인지 보조 (전부 저비용)**
- **고스트 미리보기** — 확정 전 반투명 표시
- **드롭 섀도우** — 스트로크가 지형에 그림자를 떨어뜨린다. 인간이 깊이를 읽는 방식은 그림자다
- **커서 상태 표시** — 앵커 가능 여부, 잉크 잔량

**정직한 대가:** 게임플레이는 사실상 **2.5D**가 된다. 3D는 룩(귀여운 캐릭터, 아기자기한 맵)과 카메라를 위한 것이고, 진짜 3차원 공간에 자유롭게 선을 긋는 게임은 아니다. 이 트레이드를 받아들이는 것이 컨셉의 전제다.

## 6. 협력 창발 — 규칙 추가 없이 나온다

**손이 닿는 곳만 그릴 수 있으므로, 더 높은 곳에 그리려면 친구가 들어올려야 한다.**

어깨 태우기, 던져주기, 발판을 대준 뒤 그 위에서 그리게 하기 — 규칙을 하나도 추가하지 않았는데 4인 플레이를 해야 할 이유가 생긴다. 좋은 코어 메카닉의 신호다.

---

## 7. 등반 · 실패 규칙

- **Only Up식 전체 리셋은 채택하지 않는다.** Only Up은 레이지 게임으로 화제성만 얻고 스토어에서 내려갔다. PEAK가 1000만 장 팔린 이유는 훨씬 관대해서다
- 낙하 페널티: **구간 후퇴 + 잉크 손실**
- 4인에서 낙하는 비극이 아니라 코미디여야 한다 → **떨어지는 친구를 그림으로 받아내는 것**이 게임의 하이라이트

## 8. 인원 스케일 (1~4명)

억지 규칙이 필요 없다. 등반은 인원과 무관하게 성립하는 목표이고, 양 끝단이 이미 시장에서 검증됐다.

| 인원 | 성격 | 시장 선례 |
|---|---|---|
| 1인 | 잉크 관리 물리 퍼즐 | Only Up, Getting Over It |
| 2인 | 서로 발판을 대주는 협동 | Chained Together, Bread & Fred |
| 4인 | 낙서가 뒤엉키는 사회적 난장판 | PEAK |

## 9. 차별점

수직 등반 코옵은 **이미 포화**다 — PEAK(1000만 장, 2025 골든조이스틱 최고 멀티플레이어), Chained Together, Surmount, Climb Quest, Bread & Fred, Fling Friends.

**그러나 드로잉이 있는 등반 게임은 없다.**

- 등반은 훅이 아니라 **장르 관습**으로 취급한다 → 유저 학습 비용 0
- **차별점의 100%는 펜이다.** 트레일러 3초 안에 펜이 나와야 한다
- 인접 선례와의 경계
  - **Grow Home** (Ubisoft, 2015) — 손에서 뻗어나가는 줄기로 등반로를 만들고 양손을 개별 조작하며 사거리가 제한된다. **가장 가까운 조상이지만 싱글플레이**
  - **마인크래프트 기둥 쌓기** — "팔 길이 건설로 오르기"의 민속적 원형
  - **Crayon Physics Deluxe** — 드로잉→물리의 정본이지만 **멀티플레이 없음**
  - **Kirby and the Rainbow Curse** — 1명이 그리고 3명이 플랫포밍. Wii U 독점, 게임패드 필수. **나머지 3명이 할 게 없어서 실패했다** → 우리는 전원이 각자 그린다
  - **PEAK** — 등반 문법은 같지만 창작 요소가 없다

> 메카닉 계열(사거리 제한 건설)은 확립돼 있다. **프리핸드 스트로크가 건설 단위이고 + 잉크 게이지가 뒤를 지우도록 강제하고 + 4인 코옵 등반인 조합**이 비어 있는 자리다.

## 10. 웃김의 엔진

그린 것은 실물이므로 **모두에게 적용된다.** 내 발판은 남도 밟고, 내 벽은 내 길도 막는다. 선의로 그린 것이 남을 죽인다.

대표 클립이 될 순간:

> **친구가 밟고 서 있는 발판을 지우는 것.** "내 발판 지우지 마!!!"

실수로도 되고 고의로도 된다. 이 모호함이 프렌드슬롭의 심장이다.

## 11. 미결 사항 (결정 필요)

| # | 쟁점 | 현재 권고 |
|---|---|---|
| 1 | **조준식 vs 궤적식** — 손에서 마우스로 뻗어 그리는가, 손 자체가 펜촉이라 캐릭터를 움직여 그리는가 | **조준식.** 궤적식은 순환 문제가 있다 (내가 이동해야 그려지니 "아직 갈 수 없는 곳으로 가는 길"을 만들 수 없다). 다만 스파이크에서 둘 다 만져본다 |
| 2 | 잉크 게이지가 **개인별인가 팀 공유인가** | **개인별 + 색상 구분.** 공유면 한 명이 다 써서 나머지 3명이 아무것도 못 하는 데드타임이 생긴다 (Rainbow Curse를 죽인 문제). 색이 다르면 "누가 이거 그렸어"가 즉시 읽혀 웃김이 산다 |
| 3 | **남의 낙서를 지울 수 있는가** | **지울 수 있고, 잉크는 원 소유자에게 환급.** 지우기가 이타행위와 살인 사이에서 모호해진다 |
| 4 | 화살 회수 방식 (소모품 / 쿨다운 / 잉크 비용) | **회수형.** 쏜 화살을 주우러 가야 하니 등반 루프와 엮이고, 친구가 주워 던져줄 수 있어 협력이 또 생긴다 |
| 5 | 화살이 §6 협력 창발을 잠식하는 문제 | 프로토타입 이후. 잉크 비용을 크게 잡는 쪽이 1순위 완화책 |
| 6 | 로그라이트 메타(랜덤 탑, 언락) 도입 | 프로토타입 이후 판단. 화살은 이 트랙의 유력 언락 |
| 7 | 런 길이 / 정점 존재 여부 | 프로토타입 이후 판단 |
| 8 | 온라인 / 로컬 / 둘 다 | 온라인 필수(프렌드슬롭 전제), 프로토타입은 로컬로 검증 |
| 9 | 정식 타이틀명 | `DOODLE UP`은 가칭 |

## 12. 프로토타입 범위

P0는 두 단계로 나눈다. 카드·수치·증거 규격의 정본은 `docs/prototype-execution-plan.md`를 따른다.

- **Gate A 필수 — 솔로 M+K 입력 생존:** 회색 박스 3-task 코스 · **손 원점 사거리 제한 드로잉** · 공통 stroke backend · Aim/Trajectory thin adapter · 정적 캡슐 발판 · 잉크 게이지+환급 · 고스트 미리보기
- **Gate A PASS 뒤 Gate B — 로컬 2인 사회성 smoke:** 동일 모델 gamepad 2개 · 독립 색/소유권/잉크 · 서로의 발판 사용·삭제·환급
- **Gate A PASS 뒤 조건부 기술 검증:** 공중 동적 낙하와 terrain anchor 분류

## 13. 기술 메모

- **스트로크 → 콜라이더:** 점 배열 → Douglas-Peucker 단순화 → **캡슐 콜라이더 연쇄**로 근사
  - `MeshCollider`는 쓰지 말 것. non-convex 문제 + 성능 + 네트워크 비용이 삼중으로 터진다
  - 캡슐 체인은 물리 안정성 · 성능 · 동기화가 전부 유리
- **팔 IK:** 손이 실제로 그리는 위치에 있어야 하므로 필요. 프로토타입에선 손을 트랜스폼 하나로 대체
- **네트워크:** 스트로크는 압축된 점 배열로 전송, 각 클라가 동일 재구성. **호스트 권위 물리 + 클라 보간.** 협력 게임이라 공정성 요구가 낮아 이 방식이 충분하다 (R.E.P.O.도 동일)
- **아트 비용:** 아기자기한 3D는 비싸지만 **수직 등반은 에셋 재사용에 최적**이다. 모듈러 지형 조각을 수직으로 반복 (PEAK 방식). 아트는 재미 검증 후에 붙인다
- **수직 맵 주의:** 오클루전/스트리밍 필요, 낙하 거리가 길어 물리 활성 범위 관리 필요
