# 통로·구역 재설계안 — 4인 확장 + 방 증설 (v3, 제안 단계)

정본 아님. `ship-scale-and-density-v1.md` §0.1/§2.5/§3.1/§3.5의 확정값에 대한 **개정 제안**이며, PM/사용자 검토 전까지 시공 지시가 아니다.

**v1 → v2 변경 이유.** v1은 "구역 수 3개 유지"를 전제로 엔진실 우회 덕트만 제안했다. 사용자가 직접 "방을 늘려야지... 방 3개면 너무 좁아"라고 답해 그 전제가 뒤집혔다(§3.2 요청 2-c 동결 해제, PM 확인). v2는 방 증설을 반영하고, v1의 우회 덕트 개념은 폐기하지 않고 새 위상에 맞게 승계한다(§5).

**v2 → v3 변경 이유.** 사용자가 4구역(조종석/전력실/냉각실/산소실, 38m) 확정 뒤 구역을 더 늘리라고 추가 지시했다(휴게실·화장실·숙소 예시, "등등"). v2의 "5계통-구역 1:1" 논리로는 이 방들이 정당화되지 않는다 — 시스템 상태가 없는 순수 생활공간이기 때문이다. v3는 이를 별도 카테고리(§9)로 다룬다.

## 0. 결론

1. **4개 방으로 늘린다 — 조종석 / 전력실 / 냉각실 / 산소실.** 엔진실(전력+열 두 계통이 한 방에 뭉쳐 있던 방)을 제자리에서 둘로 쪼갠다. 새 계통을 발명하지 않는다 — 이미 있던 5계통 중 둘을 방으로 분리할 뿐이다(§2.1).
2. **CT-09 선체 치수는 바뀐다 — `36m → 38m`(`×6.0m`는 유지).** 제자리 분할(성장 `0m`)은 구역 부피비 가드레일(`RG-1(3)`, `≤3배`)을 `3.5배`로 넘긴다. `+2m`만 보태면 `2.8배`로 돌아온다. 조종석·산소실 쪽은 좌표만 `±1m` 옆으로 밀릴 뿐 형상·검증값은 그대로다(§2.2).
3. **개구부 `5`곳, 문 `3`개, 게이지는 여전히 `2`개.** 신설 문(전력실↔냉각실)에는 게이지를 안 단다 — "게이지는 통로 쪽 한 면에만"이라는 기존 규칙상 이 문은 양쪽 다 방이라 애초에 통로 쪽 면이 없다(§3).
4. **검증 로직 중 진짜 알고리즘 변경이 필요한 것은 `Resolve()` 하나다.** `SIMUL_ZONES ≤ 2`의 상수 `2`, 게이지 `T5` 판독 로직, 구역오디오 `T3` 감쇠 로직은 상수 변경이 아니라 **좌표 재도출 + 재실행**으로 충분하다. 단, 구역 쌍 수가 `3 → 6`으로 늘고, 신설 문이 만드는 **3중 개구부 관통선** 위험이 새로 생긴다(§4).
5. **v1의 우회 덕트 개념은 승계한다, 폐기하지 않는다.** 방 증설만으로는 위상이 여전히 일직선이라 대안 경로가 저절로 안 생긴다 — 오히려 강제 통과 지점이 `2`곳에서 `3`곳으로 늘어 병목이 더 심해진다. 덕트가 우회하는 대상만 "엔진실"에서 "전력실+냉각실"로 바뀐다(§5).
6. **생활공간(휴게실/화장실/숙소) `3`개를 압력존 바깥의 단일 부속 블록으로 추가한다.** `ZonePressure` 배열에 안 들어간다 — 게이지도, `SIMUL_ZONES` 검사도, `RG-1` 가드레일도 적용 대상이 아니다(읽을 상태값 자체가 없다). 대신 `SHIP_LENGTH`(압력존 정의값, `38m`)는 안 바꾸고 별도 부속 길이(`+10m`)로 분리한다. 이 블록은 `4`인 게이트의 대안 경로 요건에 기여하지 않는다 — 그 몫은 여전히 우회 통로(§5)가 맡는다(§9).

## 1. 왜 방 증설만으로는 부족한가

사용자 요청("방을 늘려야지")과 `concept-draft.md` §9의 4인 게이트 조건("대안 경로")은 **서로 다른 요구다.** 방을 셋에서 넷으로 늘려도 위상이 `조종석-통로A-전력실-냉각실-통로B-산소실`처럼 여전히 일직선이면, 조종석에서 산소실로 가는 경로는 그대로 하나뿐이고 **강제로 지나야 하는 문이 `2`개에서 `3`개로 늘 뿐이다.** 방 증설이 밀도·서사(계통별 방)는 개선해도, 4인 게이트가 요구하는 "대안 경로"는 여전히 `0`개다. 이 둘은 같이 풀어야 하는 별개의 항목이며, 방 증설은 §2가, 대안 경로는 §5가 각각 답한다.

## 2. 방 증설 — 전력실 / 냉각실 분할

### 2.1 왜 이 둘로 쪼개는가

`ship-elements-and-situations-v1.md`가 이미 확인한 계통-구역 불일치: 5계통(추진/전력/산소/선체/열) 대 기존 3구역. 조종석=추진, 산소실=산소는 거의 1:1인데, **엔진실 한 방이 전력(`BusPower`, A-3)과 열(`EngineHeat`, A-1) 두 계통을 떠맡고 있었다.** 이미 서로 다른 상태 변수인 둘을 방만 하나로 묶어놨던 것이므로, 쪼개면 계통:방 대응이 거의 1:1이 되고 새 서사를 발명할 필요가 없다.

**5번째 방(선체 전용)은 기각한다.** `HullIntegrity`/파공은 특정 방에 안 묶인 앰비언트 속성이다 — `ship-elements-and-situations-v1.md`가 "조종석 자체에 파공이 난 프리셋"을 이미 확인했다(조종석에서도 파공 발생 가능). 어느 방에서든 이미 파공이 날 수 있는데 별도 "선체실"을 만들 계통적 근거가 없다. 4개면 충분하고, 5개는 근거 없는 증설이다.

### 2.2 선체 치수 — `36m → 38m`

**제자리 분할(성장 `0`)은 가드레일을 넘긴다.** 엔진실 `8m`를 그대로 `4m + 4m`로 쪼개면:

- 전력실/냉각실 구역 = `4m × 6m = 24m²` (각자 자기 방만, 통로 귀속 없음)
- 조종석/산소실 구역 = 기존 그대로 `84m²` (안 건드림)
- 비율 `84 / 24 = 3.5배` — `RG-1(3)` 가드레일(`≤ 3배`)을 넘긴다

**`+2m`만 더하면 돌아온다.** 엔진실 블록을 `8m → 10m`로 키우고 정확히 반으로 쪼개면:

- 전력실/냉각실 구역 = `5m × 6m = 30m²` 각각
- 조종석/산소실 구역 = **좌표만 `±1m` 옆으로 밀릴 뿐 크기는 그대로 `14m`(`84m²`) — 안 바뀐다.** 늘어난 `2m`를 전부 중앙 블록에 넣고 양끝 구역 길이는 손대지 않았기 때문
- 비율 `84 / 30 = 2.8배` — 가드레일 안, 여유 있음

**대안(기각) — `4`개 방 균등 분할.** 조종석/산소실까지 같은 크기로 맞추려면 선체가 `~50m`까지 늘어난다. 이러면 `RG-1` 전 항목·게이지 판독 거리·사이렌 도달·탈출 경로가 전부 재계산 대상이 되어 카드 스코프를 크게 벗어난다. `+2m` 안이 "기존 검증 최대 보존"에 맞는 선택이다.

**결론: CT-09를 `36m × 6.0m → 38m × 6.0m`로 개정 제안한다.** 폭(`6.0m`)은 안 바꾼다 — 폭 확장의 근거였던 시야 차단 요구(§3.5)는 구역 수와 무관하다.

## 3. 물리 레이아웃 — 개구부/문/게이지 재번호

```
조종석 ─[0]─ 통로A ─[1·문·게이지]─ 전력실 ─[2·문]─ 냉각실 ─[3·문·게이지]─ 통로B ─[4]─ 산소실
        x=-19        x=-11        x=-5      x=0     x=+5        x=+11       x=+19
```

- 개구부 `0`(조종석↔통로A) · 문 없음 — 기존과 동일, 좌표만 밀림
- 개구부 `1`(통로A↔전력실) · **문·게이지** — 기존 개구부 `1`을 `x=-4`에서 `x=-5`로 `1m` 평행 이동. `z` 범위·`GAP_Z`·배플 관계는 그대로다(좌표 재도출일 뿐, 형상은 불변)
- 개구부 `2`(전력실↔냉각실) · **문, 게이지 없음** — **신설.** `x=0`
- 개구부 `3`(냉각실↔통로B) · **문·게이지** — 기존 개구부 `2`를 `x=+4`에서 `x=+5`로 이동
- 개구부 `4`(통로B↔산소실) · 문 없음 — 기존과 동일, 좌표만 밀림

**개구부 `2`(신설)의 `z` 위치가 새로 검증받아야 한다.** 기존엔 개구부 `1`·`2`가 서로 `z` 오프셋(각 `[-0.6,+1.0]` / `[-3.0,-1.4]`)이라 축선 관통이 없었다. 개구부가 셋(`1`-`2`-`3`)이 되면 **셋이 한 축에서 순서로 안 겹치는지**를 같이 봐야 한다 — 쌍(pairwise) 비겹침만으론 부족할 수 있다. 가운데 문도 폭을 가지므로 셋을 잇는 직선이 존재할 여지가 남는다. `game-tech-director` 확인 필요.

## 4. 검증 로직 영향 — 알고리즘 변경 vs 좌표 재도출

PM이 요청한 "고정 상수가 아니라 알고리즘 자체" 질문에 대한 항목별 답이다.

| 대상 | 변경 종류 | 내용 |
|---|---|---|
| `LastShiftZonePressure.Resolve()` | **알고리즘 변경** | 현재 `if x<=A return Cockpit; if x>=B return LifeSupport; else EngineRoom` — 2-threshold/3-분기. `4`구역이면 `3`-threshold/`4`-분기 구조로 다시 짜야 한다. 상수 하나를 더 넣는 게 아니라 분기 형태 자체가 바뀐다 |
| `VerifyZonesCannotSeeEachOther()` | **검사 범위 확장 + 신규 케이스** | 구역 쌍 `C(3,2)=3 → C(4,2)=6`. 신설 쌍(전력실-냉각실)은 문 하나로 **직접 인접**하는 케이스라 기존 어느 쌍에도 없던 형태 — 새 로직이 필요할 수 있다 |
| `SIMUL_ZONES ≤ 2` | **상수는 불변, 검사만 확장** | "한 지점에서 `3`구역 이상 동시 판독 금지"라는 규칙 자체는 구역 수와 무관하게 그대로다. 다만 §3의 `1`-`2`-`3` 3중 개구부 관통선이 실제로 성립하면, 통로 안 특정 지점에서 전력실+냉각실(+운 나쁘면 조종석 일부)까지 동시에 걸리는 새 실패 모드가 생긴다 — `T4`가 이 케이스를 새로 검사해야 한다 |
| 게이지 `T5` | **상수 재사용, 좌표만 재도출** | `5.5m`/`2m` 판독 임계값은 개구부 단위 로직이라 구역 수와 무관하다. 개구부 `1`·`3`의 새 좌표(`x=∓5`)에서 재실행하면 된다 |
| 구역오디오 `T3` | **일부 알고리즘 영향** | 감쇠·`DOOR_TIME` 로직 자체는 좌표 무관 재사용 가능. 다만 **`2D` 사이렌 규칙**(§3.1.2 "제3구역은 소거법으로만 특정")이 신설 쌍(전력실↔냉각실)에도 그대로 적용되는지, 전력/열 계통 상황(`S-P*`, `S-H*`)의 사이렌이 어느 `2`구역을 도달 범위로 삼을지는 **재검증이 아니라 새 설계 결정**이다 — `game-balance`/`game-planning` 공동 확인 필요 |

## 5. 여전히 필요한 것 — 우회 통로 (v1 덕트 개념 승계)

v1이 제안한 "엔진실 우회 정비 덕트"는 폐기하지 않는다 — §1이 지적한 대로 방 증설만으로는 대안 경로가 안 생기므로 오히려 더 필요해졌다. 바뀌는 것은 우회 대상뿐이다: **엔진실 하나가 아니라 전력실+냉각실 둘 다를 우회한다.**

- 진입점은 그대로 통로A 쪽(개구부 `0` 근처, 조종석 구역 안)·통로B 쪽(개구부 `4` 근처, 산소실 구역 안). 전력실·냉각실 내부에는 진입점을 두지 않는다.
- 폭 `0.9m`, 웅크림 이동, `SuitOxygen` 소모 취지도 그대로다.
- **꺾임 조건은 재확인이 필요하다.** v1은 엔진실 하나만 우회하면 됐지만, 이제 우회 구간이 방 둘(전력실+냉각실)만큼 길어져 직선 구간이 늘어난다. 최소 `1`회 직각 꺾임으로 충분한지, 구간이 길어진 만큼 추가 꺾임이 필요한지는 실제 도면이 나와야 확정된다 — `game-tech-director` 확인 필요.
- 덕트의 존재 목적(§9 4인 게이트의 "대안 경로")은 안 바뀐다: 산소 비용이 있어야 "급할 때만 쓰는 진짜 우회로"가 되고, 비용이 없으면 주 통로 설계(배플·게이지·판독 3단) 전체가 장식이 된다.

## 6. 구체 시나리오 (갱신)

```
운석이 전력실에 충돌. 조종석·산소실 양쪽에서 대응이 필요하다

A1  조종석에서 조종 입력 유지 (hold)
A2  전력실로 가서 배전반 작업
B1  산소실에서 서리 확인 중
B2  냉각실에서 냉각 결합부 작업

A2 는 전력실에, B2 는 냉각실에 — 이제 둘은 서로 다른 방에 있다.
전력실↔냉각실 사이 문(개구부 2)이 있어서 "잠깐 넘어가서 상태 확인"이 가능하다.
A2가 배전반 작업 중 냉각 결합부 소리가 심상치 않으면, 문을 열고
냉각실로 넘어가 B2 상태를 직접 보고 다시 돌아올 수 있다 — 3구역(3인)
위상에서는 아예 없던, 방 두 개가 나뉘어야 생기는 상호작용이다.

이때 산소실 압력이 갑자기 0.15 밑으로 떨어진다 (전선 사이렌)
B1 은 A1 에게 알려야 한다. 기존 위상이면:

  통로B 진입 → 냉각실 통과 → 전력실 통과(문 2개, A2·B2 작업 중) → 통로A → 조종석
  네 사람이 한 지점이 아니라 두 문을 순서대로 다 거친다 — 3구역보다 더 길어졌다

우회 통로가 있으면:

  B1 이 산소실 쪽 통로 입구로 들어간다 (SuitOxygen 소모 감수)
  전력실·냉각실 어느 쪽도 거치지 않고 통로A 쪽 출구로 나와 조종석에 바로 알린다
  A2·B2 는 방해받지 않는다
```

전력실↔냉각실 사이 문 하나가 §9 4인 조건의 "물건 간섭·동시 구조"의 다른 절반—**방이 나뉜 두 사람이 서로의 상태를 확인하러 잠깐 넘어가는 것**—을 채울 후보가 될 수 있다는 점은 이번에 새로 발견한 것이며, 아직 검증되지 않았다(§8).

## 7. 트레이드오프

- **CT-09 변경은 좌표 재기재를 요구하지만 형상 재설계는 아니다.** 조종석·산소실 쪽 배플·게이지·개구부 형상은 `±1m` 평행 이동만 하면 되고, 재검증이 아니라 좌표 갱신이다. 다만 문서·씬 양쪽에서 `x` 값을 쓰는 모든 곳(개구부 좌표, 배플 좌표, RG-1 거리 계산)을 빠짐없이 갱신해야 하는 실무 부담은 있다.
- **`RG-1(2)` 마진이 더 얇아질 수 있다.** 기존 최악 복구 경로 `31.5초`(여유 `1.27배`, 세 가드레일 중 가장 얇음)에 문이 하나 늘면서 `DOOR_TIME 0.8초`가 추가되는 경로가 생길 수 있다. `game-balance` 재계산 필요 — 이미 얇은 마진이라 우선순위 높음.
- **`RG-4`(파공 구역 조합) 재계산 필요.** 파공 발생 구역이 `3`곳에서 `4`곳으로 늘어난 만큼 조합·확률 밸런스를 다시 잡아야 한다.
- **개구부 `2`의 `z` 위치가 §3(관통선)·§4(`SIMUL_ZONES`)·§5(덕트 꺾임) 셋 다의 선행 조건이다.** 이 좌표가 정해지기 전까지 세 항목 모두 확정 검증이 아니라 방향 제안 단계로 남는다.

## 8. 미결 사항

1. 개구부 `2`(전력실↔냉각실)의 정확한 `z` 위치와 `1`-`2`-`3` 3중 관통선 검사 방법 — `game-tech-director`
2. 전력/열 계통 사이렌이 `2D`(신설 쌍 포함) 규칙을 그대로 따르는지, 새로 설계해야 하는지 — `game-balance` + `game-planning` 공동
3. `RG-1(2)`/`RG-4` 재계산 — `game-balance`
4. 우회 통로의 꺾임 횟수(구간이 길어진 만큼 추가 필요한지) — `game-tech-director`
5. §6의 전력실↔냉각실 문이 4인 게이트의 "동시 구조" 요건을 실제로 채우는지 — 씬이 나온 뒤 체감 판정 대상(결정 아님)
6. 덕트 폭 `0.9m`의 아이템 반입 제한 의도 여부 — v1부터 이월, 여전히 미결
7. `CT-11`(통로 밀도) 재개 시 "우주선 느낌" 체감 재판정 — 사용자

## 9. 생활공간 확장 (v3) — 휴게실 / 화장실 / 숙소

### 9.1 몇 개, 왜 이 셋인가

**사용자가 예시로 든 셋(휴게실/화장실/숙소)으로 제안을 마감한다.** "등등"은 비확정 표현으로 받아들였다 — 목록을 임의로 늘리지 않는다. 셋을 넘는 추가가 필요하면 어떤 방인지부터 사용자 확인이 먼저다(§9.5 미결).

이 셋을 고른 근거는 v2의 "계통-구역 1:1"과 다른 축이다. 계통 상태가 아니라 **"매 항해 4인이 실제로 거주하는 배"라는 서사**가 근거다.

- **숙소**: 4인 벙커. `§9`(concept-draft) "매 항해 역할 교환"의 물리적 근거지 — 교대 시점의 자연스러운 집합 지점이 된다
- **휴게실**: 테이블+의자. 항해 시작 전 브리핑 장면과 겸용 가능 — 신규 공간을 전투/판정용이 아니라 세션의 시작/종료를 감싸는 용도로 쓴다
- **화장실**: 소형 편의 공간. 서사적 근거는 가장 약하지만 실제 우주선/잠수함류 매체가 반드시 갖는 공간이라 "우주선 느낌"에 대한 기여도가 크기에 비해 콘텐츠 비용이 가장 낮다(`~4m²`)

### 9.2 배치 — 단일 부속 블록, 산소실 옆

```
... 통로B ─[4]─ 산소실 ─[생활 진입로·문 1개]─ [화장실 2m|숙소 4m|휴게실 4m]
                                x=+19                    +10m 부속 블록
```

**압력존 스판에 안 넣는다.** 산소실 끝(`x=+19`)에 문 하나로만 연결되는 별도 블록으로 붙인다. 이유:

1. **`Resolve()` 변경이 필요 없다.** 이 블록의 좌표는 기존 `x >= LifeSupportMinX → LifeSupport` 분기가 이미 처리하는 범위 밖(또는 그 분기가 그대로 흡수)이다. `§4`(v2)의 `3`-threshold 구조에 네 번째 분기를 또 넣을 필요가 없다
2. **`RG-1` 전 항목이 적용 대상이 아니다.** `RG-1`은 압력/사이렌/탈출이 실제로 발생하는 구역의 가드레일이다. 이 블록엔 상황(`S-*`)이 안 걸리므로 최장 횡단·최악 복구 경로·부피비 어느 것도 계산 대상이 아니다 — 단, 이 방을 지나야만 하는 필수 경로가 되면 안 된다는 전제가 있다(§9.4)
3. **왜 산소실 쪽인가.** 근거는 강하지 않다 — 화장실·숙소의 배관/생명유지 설비가 산소실 계통과 인접한 것이 개연성이 조금 더 있다는 정도다. 조종석 쪽으로 붙여도 구조적으로 동일하다. 최종 위치는 `art`/`tech` 판단으로 넘겨도 된다

### 9.3 게이트/게이지/판독 규칙 적용 여부 — 전부 면제

| 규칙 | 적용 여부 | 이유 |
|---|---|---|
| `ZonePressure` 배열 | **면제** | 압력 상태가 없는 방. 배열에 슬롯을 안 만든다 |
| 게이지 | **면제** | 표시할 상태값이 없다 |
| `SIMUL_ZONES ≤ 2` | **면제** | 애초에 "구역"이 아니라 판독 대상 자체가 없다 |
| 시야차단(`A3`) | **면제** | 압력존과 인접하지 않게 뒀다(단일 진입로) — 새지도 섞이지도 않는다 |
| `DOOR_TIME 0.8s` | **미결** | 압력 평형 목적이 없는 문이라 지연을 걸 이유가 약하다. 여닫이 문으로 단순화할지는 `tech` 판단 |
| `SuitOxygen` 소모 | **면제** | 가압 구역이라 상시 대기 상태와 동일 취급 |

### 9.4 필수 전제 — 막다른 방이어야 한다

이 블록이 압력존 관련 어떤 경로(탈출, 상황 대응)에도 필수 경유지가 되면 안 된다. 진입로가 하나뿐이고 안쪽이 막다른 구조(관통 통로 아님)이면 자동으로 충족된다 — **디자인 조건이지 추가 검증 항목이 아니다.**

### 9.5 `4`인 게이트 대안 경로 기여 — 기여하지 않는다

**명시적으로 아니라고 답한다.** 막다른 부속 블록은 기존 두 구역 사이를 잇는 우회로가 될 수 없다. `concept-draft.md` §9의 "대안 경로" 요건은 여전히 §5의 우회 통로가 전담한다. 생활공간과 대안 경로를 같은 방으로 겸하게 하려면(예: 숙소를 관통형으로 바꿔 통로B와 산소실을 잇는 두 번째 문을 단다) 두 가지가 깨진다 — 서사적으로 "잠 자는 방을 업무 동선이 관통"하는 게 어색해지고, 막다른 방 전제(§9.4)가 사라져 `RG-1` 면제 근거도 같이 사라진다. **권장하지 않는다.**

### 9.6 미결 사항 (v3)

1. **"등등"의 나머지.** 사용자가 셋 외에 더 원하는 방이 있는지 — 있다면 이름부터 필요
2. **부속 블록 위치**(산소실 쪽 vs 조종석 쪽) — 근거가 약해 `art`/`tech` 판단으로 넘길 수 있음
3. **문 종류**(압력 문 vs 단순 여닫이 문, `DOOR_TIME` 적용 여부) — `tech`
4. **아트 비용.** `CT-11`(통로 밀도)과 별개로 생활공간 전용 소품(침대·테이블·세면대)이 신규 필요 — 카드 스코프 판단은 PM

## 10. 용어

- **주 통로**: 조종석-통로A-전력실-냉각실-통로B-산소실 직선 위상 전체를 가리킨다.
- **우회 통로**: 이 문서가 승계 제안하는, 전력실+냉각실을 모두 건너뛰는 별도 연결 구조. 구역이 아니다. (v1의 "정비 덕트"와 동일 개념, 우회 대상만 갱신)
- **대안 경로**: `concept-draft.md` §9 4인 게이트 조건의 표현을 그대로 쓴다.
- **생활공간**: `ZonePressure` 배열 밖의 비압력 방(휴게실/화장실/숙소). "구역"과 구분해서 쓴다 — 구역은 압력 상태를 갖는 방만 가리킨다.
