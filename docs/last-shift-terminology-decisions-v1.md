## 1. 중앙 승강기 — 승인, 단 변형이 하나 더 있다

**확정: 플레이어 문구에서 이 설비는 `중앙 승강기` 하나로 부른다.**

### 1.1 실제로 섞여 있는 변형은 4개가 아니라 6개다

카드는 `코어 / 중앙 승강구 / 승강기 / 승강 플랫폼` 4개를 적었다. 코드와 CSV 를 직접 세면 플레이어에게 노출되는 변형은 다음과 같다.

| 변형 | 나오는 자리 | 플레이어 노출 |
|---|---|---|
| `승강기` | `LastShiftTutorialCopy.cs:123` | O |
| `승강구` | `LastShiftTutorialCopy.cs:124` `:130`, CSV `A4_070` `S_060` | O |
| `중앙 승강구` | CSV `A3_040` `A3_090` | O |
| `코어` | `LastShiftNarrationScript.cs:145` `:181`(한 줄에 2회) | **O — 내부 용어가 아니다** |
| `승강로` | CSV `A3_060` `A4_020` | **O — 카드 누락분** |
| `승강 플랫폼` | `LastShiftNarrationScript.cs:188` | X (트리거 라벨) |

`승강로` 가 카드 목록에서 빠져 있었다. writer 가 이 문서 표를 그대로 치환 목록으로 쓰면 된다.

### 1.2 플레이어가 실제로 겪는 장면

`LastShiftTutorialCopy.cs:123-124` 는 **한 단계 안에서** 이렇게 말한다.

- 안내: `가운데 승강기가 선외로 통하는 유일한 길이다`
- 재촉: `가운데 승강구로 갈 것 — 방 이름은 M 지도에 있다`

두 줄이 연속으로 뜨는데 같은 물체를 `승강기` 와 `승강구` 로 부른다. 그 다음 화면의 단계 제목은 `중앙 승강구`(`:130`)고, 본문은 다시 `승강기에 올라서면`(`:131`)이다. 플레이어가 배우기도 전에 이름이 세 번 바뀐다.

### 1.3 `코어` 예외 범위 정정

카드는 "코드/내부 문서의 `코어`는 유지"라고 적었지만, `코어` 는 **나레이션 본문에 그대로 들어가 있다**:

- `LastShiftNarrationScript.cs:145` — `가운데 구조물은 코어. 지금은 막혀 있음.`
- `LastShiftNarrationScript.cs:181` — `코어가 그 길임. 위로 올라가 밖으로 나감.` / 재촉 `코어로 갈 것.`

이 세 자리는 유지 대상이 아니라 **교체 대상**이다. 유지되는 `코어` 는 코드 식별자(`PlazaCore`, `SIMUL_ZONES` 판정), 코드 주석, 그리고 기획 정본 문서(`central-plaza-hub-layout-v1.md`, `central-lift-eva-ascent-v1.md`) 안의 서술뿐이다.

### 1.4 트레이드오프

- `중앙 승강기` 는 6자로 기존 `코어`(2자)보다 길다. 나레이션은 짧은 문장이 원칙(`Quiet`/`Short` 큐)이라 줄이 늘어난다. **완화:** 첫 등장만 `중앙 승강기`, 같은 블록 안 이후 언급은 `승강기` 로 줄인다. `승강기` 는 다른 설비와 안 겹치므로 축약해도 모호하지 않다.
- CSV `A3_040` `A3_090` 의 `중앙 승강구` 는 **도면 카탈로그의 구매 항목 이름**이다(`카탈로그에 든 것은 중앙 승강구 하나다`). 즉 문안만이 아니라 카탈로그 항목의 표시 이름(`kind.Name`)도 같이 바뀌어야 화면과 대사가 일치한다 — tech 몫(§6-2).

## 2. 승강기 발판 — 조건부 승인

**확정: 첫 등장은 `승강기 발판`, 같은 구간 안 이후 언급은 `발판`.**

용어집 v2 는 `승강기 발판` 을 통짜로 쓰라고 적었지만, 현행 플레이어 문구는 이미 `발판` 단독으로 쓰고 있고 그게 더 잘 읽힌다.

- `LastShiftTutorialCopy.cs:132` — `발판이 시계의 시작선이다. 올라설 것`
- `LastShiftNarrationScript.cs:189` — `발판이 산소 시계의 시작선임. 지금부터 흐름.`

이 두 줄은 **이미 승강기 위에 올라선 직후**에 뜬다. 앞 줄에서 `중앙 승강기` 를 말한 다음이라 `승강기 발판이 시계의 시작선이다` 는 같은 말을 두 번 하는 셈이다. 반면 승강기를 아직 안 본 상태에서 `발판` 만 나오면 무슨 발판인지 모른다.

그래서 규칙을 이렇게 정한다 — **승강기를 아직 안 지칭한 문맥에서 처음 나오면 `승강기 발판`, 승강기가 이미 화제인 문맥이면 `발판`.** 이건 용어집 v2 의 `설명해서 유지할 용어` 표(감압·재가압·배전반)가 이미 쓰는 첫 등장/이후 표현 패턴과 같은 방식이다.

**트레이드오프:** 판정이 문맥 의존이라 writer 가 줄마다 판단해야 한다. 통짜 규칙보다 손이 더 간다. 그래도 위 두 줄에 통짜로 넣으면 40자 제한(용어집 `작성 기준`)에 `발판이 산소 시계의 시작선임` 이 밀리므로 실익이 있다.

`승강 플랫폼` 은 트리거 라벨(`LastShiftNarrationScript.cs:188`)과 기획 정본(`central-lift-eva-ascent-v1.md` §0-6, §4.1)에만 남긴다. 플레이어 노출 0건이라 손댈 것이 없다.

## 3. 승강기 위쪽 / 바깥 해치 — 승인, 용법을 갈라 둔다

**확정: 지점을 가리키면 `바깥 해치`, 방향을 가리키면 `승강기 위쪽`. `탑` 계열은 전부 폐기.**

용어집 v2 는 `승강기 위쪽 / 바깥 해치` 를 빗금으로 묶어 뒀는데, 그대로 두면 writer 가 줄마다 다시 고민한다. 실제 문장에 대 보면 갈라진다.

현행 `탑 정상` 은 두 자리 다 **도착 지점**으로 쓰인다:

- `LastShiftNarrationScript.cs:197` — `탑 정상. 여기부터 선외임.` / 재촉 `해치로 걸어 나갈 것.`
- `LastShiftNarrationScript.cs:211` — 재촉 `탑 정상으로 복귀할 것.`

여기에 `승강기 위쪽` 을 넣으면 `승강기 위쪽으로 복귀할 것` 이 되는데, 방향만 있고 어디서 멈추는지가 없다. `바깥 해치로 복귀할 것` 은 목표가 분명하다. 게다가 `:197` 은 이미 다음 줄에서 `해치로 걸어 나갈 것` 이라고 말하고 있어서, 지점 이름을 `바깥 해치` 로 맞추면 두 줄이 같은 대상을 가리키게 된다.

| 현행 | 확정 | 근거 |
|---|---|---|
| `탑 정상. 여기부터 선외임.` | `바깥 해치. 여기부터 선외임.` | 지점 |
| `탑 정상으로 복귀할 것.` | `바깥 해치로 복귀할 것.` | 지점 |
| (이동 방향을 말할 때) | `승강기 위쪽` | 방향 |

`상단 해치` 는 트리거 라벨(`LastShiftNarrationScript.cs:196` `IsAtHullTop · 상단 해치 열림`)과 정본(`central-lift-eva-ascent-v1.md` §1.4)에만 남긴다.

**주의:** `해치` 단독은 그대로 유지한다(용어집 `그대로 유지할 용어`). CSV `A3_100` 의 `해치는 기본이 닫힘이다` 처럼 배 전체의 해치 일반을 말하는 줄이 따로 있어서, 전부 `바깥 해치` 로 치환하면 안 된다.

## 4. `건설 메뉴` 기각 — 대신 `선체 도면` 을 폐기한다

### 4.1 카드와 용어집이 서로 다른 질문에 답하고 있었다

- 카드 4번: `거점 탭 / 도면 → 건설 메뉴` (구조물 설치 UI **전체**를 뭐라 부를 것인가)
- 용어집 v2 표: `지도 / 도면 → 서로 통합하지 않음` (`지도` 와 `도면` 을 합칠 것인가)

**두 질문이 다르다.** 용어집이 답한 "지도와 도면을 합치지 말라"는 맞고 그대로 유지한다 — `지도` 는 M 키로 여는 배 배치 보기, `도면` 은 자유배치 화면이고, `LastShiftTutorialCopy.cs:120` 이 이미 그렇게 못박아 뒀다(`배 배치를 보는 화면은 지도, 모듈을 놓는 화면은 도면이다`). 여기 이견 없다.

하지만 카드가 물은 것은 그게 아니라 **두 탭을 품은 화면 전체의 이름**이었고, 그건 아직 안 닫혀 있다.

### 4.2 진짜 충돌은 `선체 도면` 이다

코드를 세면 화면 구조는 이렇다(`LastShiftPlacementUi.cs`):

```
도면 화면 ─┬─ 선체 탭   (화면 표시 라벨 "선체",  :1072)
           └─ 거점 탭   (화면 표시 라벨 "거점",  :1072)
```

그런데 화면 이름이 정본 두 곳에서 **`선체 도면`** 으로 박혀 있다:

- `core-four-rooms-and-hull-schematic-v1.md:19` — "미니맵이 아니라 `선체 도면`이라고 부른다 … **화면 용어는 `선체 도면` 하나다**"
- CSV `A3_030` — `선체 도면이다. 위에서 내려다본 배 전체이고 세울 수 있는 자리는 굵게 뜬다.`

**`선체 도면` 이라는 화면 안에 `선체` 라는 탭이 하나 들어 있다.** 플레이어가 "선체 도면을 열어라"를 듣고 화면을 열면 `선체` / `거점` 두 탭이 보인다. `선체 도면` 이 화면 전체 이름인지 왼쪽 탭 이름인지 구분할 방법이 없다. 게다가 `거점` 탭은 선체와 아무 상관이 없다 — 배 밖 잔해 근처에 골조를 세우는 화면이다. 거점을 놓는 중에 화면 이름이 `선체 도면` 인 것은 그냥 틀렸다.

`선체 도면` 은 거점 탭이 생기기 전(`core-four` 시점)에 정해진 이름이고, 탭이 둘로 갈리면서 유효기간이 끝났다.

### 4.3 그럼 `건설 메뉴` 로 갈 것인가 — 아니다

**확정: 화면 이름은 `도면`. `선체 도면` 은 폐기. `건설 메뉴` 는 도입하지 않는다.**

근거 셋:

1. **`도면` 은 이미 최소 어휘 12단어 안에 있다**(용어집 v2 마지막 절). `건설 메뉴` 를 넣으면 13번째 단어가 되고, 용어집이 스스로 정한 "새 용어를 추가하려면 이 열두 단어로 설명할 수 없는 기능인지 먼저 확인한다"에 걸린다. `도면` 으로 설명이 되므로 통과 못 한다.
2. **`건설 메뉴` 를 쓰면 이름이 2층이 된다** — `건설 메뉴` 안에 `도면` 이 들어가는 구조. 카드도 "메뉴 안 설계 정보 자체만 `도면` 유지"라고 적었는데, 이러면 플레이어가 `건설 메뉴` 와 `도면` 의 경계를 배워야 한다. 한 화면에 이름 두 개는 통일이 아니라 분화다.
3. **행동을 드러내라는 요구는 탭 이름에서 채운다**(§5). 플레이어가 실제로 "무엇을 할지" 고르는 지점은 화면 이름이 아니라 탭이다. 거기에 `선체 확장` / `거점 건설` 을 넣으면 화면 이름이 명사여도 화면 안에서 행동이 읽힌다.

### 4.4 트레이드오프

- `core-four-rooms-and-hull-schematic-v1.md` §0-4 는 "화면 용어는 `선체 도면` 하나다"를 **혼용 금지 조항**으로 걸어 뒀다. 이 결정이 그 조항을 덮어쓴다. 해당 문서 §0-4 · §1 표 · §4 제목 · §4 도해 · 판정 `M-1` 다섯 자리에 갱신 표시가 필요하다(§6-3).
- `도면` 단독은 `건설 메뉴` 보다 "여기서 짓는다"가 덜 읽힌다. 이건 실제 비용이다. 다만 화면에 들어오기까지의 문맥(`필드를 비워야 도면이 열린다`, `LastShiftTutorialCopy.cs:155`)과 탭 이름이 그 몫을 대신한다고 본다.
- `미니맵` 금지는 그대로 유효하다. 이 결정은 `선체` 라는 수식어만 떼는 것이지 `도면` vs `미니맵` 구분을 건드리지 않는다.

## 5. 선체 확장 — 승인, 거점 탭도 같이 간다

**확정: 탭 이름은 `선체 확장` 과 `거점 건설`.**

카드는 `선체 탭 → 선체 확장` 만 물었다. 그런데 탭은 둘이고, 하나만 행동형으로 바꾸면 새 불일치가 생긴다 — `선체 확장` 옆에 `거점` 이 붙어 있으면 왼쪽은 동사고 오른쪽은 명사다. 짝을 맞춘다.

### 5.1 지금 화면에 뜨는 글자

`LastShiftPlacementUi.cs:1071-1072` 가 실제로 그리는 라벨은 `"거점"` 과 `"선체"` 다 — **`탭` 이라는 글자는 화면에 없다.** `선체 탭` / `거점 탭` 은 튜토리얼 문구(`LastShiftTutorialCopy.cs:161` `:177` `:179`)와 나레이션(`LastShiftNarrationScript.cs:231` `:240`), 인스펙터 툴팁(`LastShiftPlacementUi.cs:67`)에만 있는 표현이다.
