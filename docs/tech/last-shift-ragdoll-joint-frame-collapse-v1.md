## 0. 결론 먼저

1. **조인트 축이 뼈 배치와 무관하게 잡혀 있었다.** 비틀림 축과 뼈 방향의 내적이
   엉덩이 `0.21` · 어깨 `0.55` · 발목 `0.71` · 허리와 목 `0.00` 이었다. **1.0 이어야 하는 값이다.**
2. **그래서 한계가 엉뚱한 자유도를 막았다.** 엉덩이의 비틀림 허용 `-20..70` 은 다리를 제 축
   둘레로 돌리라고 준 90도인데, 축이 뼈에서 78도 어긋나 있으면 그 90도가 **굽힘**이 된다.
   스윙 콘 30/10 은 그 굽힘을 못 막는다. 다리가 몸통까지 접히는 동안 **어느 관절도 "한계 초과"
   로 안 찍힌다** — 실측 최대 초과가 1.05~1.79배뿐이었다. 콘솔이 조용했던 이유이기도 하다.
3. **프리팹이 빌더와 갈라져 있었던 것이 근인이다.** `LastShiftRagdoll` 프록시 빌더는 축을
   뼈에서 뽑고(`c6c566a`) 무릎·팔꿈치를 경첩으로 둔다(`62134a4`). 그런데 씬에 실제로 들어가는
   것은 콜라이더를 손으로 잡은 프리팹이라 그 빌더를 **한 번도 안 거쳤다.**
4. **고친 뒤:** 열네 관절 전부 비틀림 정렬 `1.00`, 무릎·팔꿈치 넷은 `HingeJoint`.
   밀쳐 넘어뜨렸을 때 최대 초과 `1.50 → 1.38`배, 낙하 `1.79 → 1.64`배.
   화면에서는 팔다리가 몸통 밖에 남는다(§4 대조 그림).
5. **규칙을 한 곳으로 모았다.** `LastShiftRagdollJointFrame` 을 빌더와 프리팹 정비 도구가 같이
   쓴다. 안 그러면 둘은 또 갈라지고, 갈라진 것을 화면으로 알아채는 데 사흘이 걸린다.

## 1. 무엇이 어긋나 있었나

`joint.axis` 는 <b>비틀림</b> 축이고 뼈가 뻗은 방향과 나란해야 한다. 실측(프리팹 정지 자세):

| 관절 | 비틀림 축 · 뼈 내적 | 뜻 |
|---|---|---|
| `DEF-thigh.L/R` (엉덩이) | **0.21** | 78도 어긋남 |
| `DEF-upper_arm.L/R` (어깨) | **0.55** | 57도 어긋남 |
| `DEF-foot.L/R` (발목) | **0.71** | 45도 어긋남 |
| `DEF-hand.L/R` (손목) | **0.31** | 72도 어긋남 |
| `DEF-spine.003` (허리) | **0.00** | 완전 직교 |
| `DEF-spine.006` (목) | **0.00** | 완전 직교 |
| `DEF-shin.L/R` (무릎) | 0.17 | 경첩으로는 오히려 맞다 — §2 |
| `DEF-forearm.L/R` (팔꿈치) | 0.31 | 같음 |

무릎·팔꿈치만 값이 "맞았다". 그 둘의 한계는 스윙 5/5 에 비틀림 80~90도인데, 이것은
**"비틀림 축을 굽힘 축으로 쓰는 경첩"을 `CharacterJoint` 로 흉내 낸 것**이다. 축을 규칙대로
뼈에 맞추면 그 흉내가 깨져 다리가 막대가 된다. 그래서 이 둘만 다르게 다뤘다.

## 2. 무엇을 바꿨나

`Last Shift/Prototype/Rebuild Ragdoll Joint Frames`
(`LastShiftRagdollJointRebuild`, 헤드리스로도 돈다) 가 프리팹의 조인트를 다시 세운다.

- **볼 조인트 10개**: 축만 다시 잡는다. 비틀림 = 뼈 방향, 스윙 = 뼈 로컬 축 중 그에 가장 수직인 것.
- **무릎·팔꿈치 4개**: `HingeJoint` 로 바꾼다. 굽힘 축은 뼈에 수직, 범위는 원래 비틀림 폭
  (무릎 80도 · 팔꿈치 90도)에 반대쪽 여유 5도.
- **한계 숫자는 안 바꾼다.** 프리팹의 한계는 `LastShiftRagdollSkinLimits` 가
  `min(원본, 스킨여유)` 로 이 프리팹에 맞춰 잡아 둔 값이다. 축과 한계를 한꺼번에 바꾸면
  나아졌는지 나빠졌는지를 못 가른다.

멱등이다 — 다시 돌려도 같은 결과가 나오고, 무엇을 바꿨는지 `tmp/ragdoll-joint-rebuild.csv` 에 적는다.

곁다리로 `LastShiftRagdollSelfCollision` 이 조인트를 `CharacterJoint` 로만 찾던 것을
`Joint` 로 넓혔다. 안 넓히면 경첩으로 바뀐 무릎·팔꿈치 쌍이 "조인트로 안 이어진 것" 으로 새어
나가 자기충돌 정책이 엉뚱한 쌍을 센다.

## 3. 측정

```powershell
# 넘어뜨려 관절 초과와 접힘을 잰다
unity run "<Project>" -- -nographics -logFile tmp/stress.log `
  -executeMethod DoodleUp.Editor.LastShiftRagdollStressProbe.RunForAutomation -stressSeconds 4 -stressTag after

# 같은 시나리오를 콘택트 시트 한 장으로 찍는다 (-nographics 를 빼야 렌더된다)
unity run "<Project>" -- -logFile tmp/shot.log `
  -executeMethod DoodleUp.Editor.LastShiftRagdollStressProbe.CaptureForAutomation -stressTag after
```

| 시나리오 | 최대 초과 (전) | (후) | 최악 관절 |
|---|---|---|---|
| 그냥 쓰러짐 | 1.05배 | 1.09배 | `DEF-shin.R` |
| 밀쳐 넘어뜨림 | **1.50배** | **1.38배** | `DEF-foot.L` |
| 1.2m 낙하 + 밀침 | **1.79배** | **1.64배** | `DEF-foot.L/R` |

**안 쓰는 지표를 적어 둔다(다시 만들지 말 것).**

- `minLimbSpan`(발↔골반 거리 비)은 **증상을 못 가른다.** 축을 고친 뒤 이 값은 그냥 쓰러짐에서
  `0.591 → 0.330` 으로 나빠졌는데 그림은 좋아졌다 — 무릎이 경첩으로 제대로 접히면서 발이
  골반에 가까워진 것이라, 정상적인 접힘과 관통이 같은 숫자로 찍힌다.
- `maxTorsoPenetration`(팔다리 ↔ 몸통 콜라이더 파고든 깊이)도 못 쓴다. 전 `8.3~10.3cm`,
  후 `8.5~10.6cm` 로 사실상 그대로인데, 이것은 **조인트로 이어진 캡슐이 관절 근처에서 원래
  겹치는 것**을 재고 있다. 그 쌍은 `enableCollision = false` 라 PhysX 가 애초에 무시한다.

결국 판정이 서는 것은 **관절 초과 배수**와 **그림**이다.

## 4. 그림

`docs/tech/evidence/last-shift-ragdoll-joint-frame-2026-08-21/{before,after}-{fall,shove,drop}.png` — 각 5장(0 · 0.4 · 0.8 · 1.6 · 4.0초).

- **밀쳐 넘어뜨림**: 전에는 마지막 세 장에서 팔다리가 몸 **안쪽으로** 말려 들어가 실루엣이
  덩어리가 된다. 후에는 네 팔다리가 몸통 **밖으로** 펼쳐진 채 엎어진다.
- **그냥 쓰러짐**: 전에는 몸이 선 자세 그대로 **수직으로 주저앉으며** 다리가 몸통에 삼켜진다.
  후에는 앞으로 넘어지고 팔다리가 보이는 자리에 남는다.

카메라는 **밀친 반대편**에 둔다. 미는 쪽에 두면 승무원이 카메라를 향해 오면서 문벽 뒤로 들어가고
남는 것은 어두운 벽 다섯 장이다(실제로 한 번 그렇게 찍혔다).

## 5. 검증

- EditMode **920/920 통과**(기존 916 + 신규 4), 실패 0 — `tmp/editmode2.xml`.
  - `EveryBallJointTwistsAroundItsOwnBone` — 볼 조인트 비틀림 정렬 `>= 0.9`.
  - `KneesAndElbowsAreHingesNotPinchedCones` — 무릎·팔꿈치가 경첩인지.
  - `HingeAxesStayPerpendicularToTheirBone` — 경첩 축이 뼈에 수직인지.
  - `ShovedRagdollKeepsEveryJointWithinItsBudget` — 실제로 4초를 밀쳐 돌리고 초과 `< 2.0`배.
- **PlayMode 에 안 넣은 이유.** 랩 씬은 빌드 세팅에 없어 `SceneManager.LoadSceneAsync` 로 못 연다.
  넣으면 프로토타입 씬이 실제 빌드에 실린다. EditMode 에서 `Physics.Simulate` 를 밟으면 같은
  PhysX 를 같은 스텝으로 돌릴 수 있고 프레임 타이밍에 안 흔들려 오히려 결정적이다.
  PlayMode 스위트에는 래그돌을 건드리는 테스트가 하나도 없다(19개 파일 중 0건).

## 6. 남은 것

1. **발목이 아직 한계의 1.38~1.64배까지 벌어진다.** 좌우 비대칭이고(왼발이 늘 먼저) 조인트
   이탈도 8cm 까지 난다. 콜라이더 크기·질량 쪽을 따로 봐야 한다.
2. **자기충돌 정책이 정지 자세에서 겹친 쌍을 하나도 못 찾는다**(`ignored=0`, `kept=91`).
   골반 콜라이더를 29.5cm → 18cm 로 줄인 뒤 겹침이 사라진 것으로 보이는데, 그러면 이 정책이
   지금 아무 일도 안 하고 있다는 뜻이다. 의도한 상태인지 확인이 필요하다.
3. **랩 씬 빌더가 여전히 낡았다.** `LastShiftRagdollLabScene.Rebuild` 는 FBX + 프록시 빌더로
   씬을 다시 만들므로, 돌리면 손으로 잡은 콜라이더 15개와 이번에 세운 조인트 14개가 사라진다.
