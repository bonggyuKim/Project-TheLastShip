# LAST SHIFT — 방 코드 기반 호스트/클라이언트 입장

## 무엇을 골랐나

같은 LAN 안에서 도는 **UDP 디스커버리 + 6자리 방 코드**. 외부 서비스 의존이 없다.

Unity Relay/Lobby 도 검토했다. NAT 통과와 코드 발급이 공짜로 따라오지만 대가가 셋이다 —
UGS 프로젝트 링크·인증 흐름·요금제라는 외부 의존이 생기고, 서비스가 죽으면 같은 방에 앉아서
하는 판까지 같이 죽고, 패키지 3종(`services.core`/`authentication`/`relay`)이 들어온다.
레퍼런스(Dear Passengers)와 실제 플레이 상황이 "친구 몇 명이 같은 네트워크에서" 인 이상
그 비용을 먼저 낼 이유가 없다. 인터넷 너머 매칭이 필요해지는 시점에 Relay 를 뒤에 끼우면
되고, 그때 바꿔야 하는 것은 `LastShiftRoomLookup` 하나다.

## 흐름

1. 호스트가 `방 열기` 를 누른다 → `LastShiftRoomCode.Generate()` 가 6자리 코드를 발급하고,
   `LastShiftNetworkSession.OpenRoom()` 이 host 를 띄운 뒤 `LastShiftRoomBeacon` 을 세운다.
2. 클라이언트가 코드를 받아 적고 `입장` 을 누른다 → `LastShiftRoomLookup` 이 배경 스레드에서
   LAN 에 질의를 뿌린다.
3. 코드가 일치하는 호스트만 유니캐스트로 답한다. 클라이언트는 **응답의 출발지 IP** 와 응답에
   실린 게임 포트로 `StartClient()` 한다.

호스트가 자기 IP 를 알 필요도, 클라이언트가 그것을 받아 적을 필요도 없다.

## 질의-응답 방향을 뒤집은 이유

흔한 구현은 호스트가 비컨을 주기적으로 브로드캐스트하고 클라이언트가 듣는 쪽이다. 그러면
**클라이언트도 잘 알려진 포트에 바인드**해야 하고, 한 PC 에서 호스트와 클라이언트를 같이
띄우는 순간 — 개발 중 가장 잦은 상황이다 — 포트가 겹친다. 그래서 방향을 뒤집었다. 잘 알려진
포트(UDP 7980)를 잡는 것은 호스트 하나뿐이고, 클라이언트는 임시 포트에서 질의를 던진다.

질의는 `255.255.255.255`, 인터페이스별 디렉티드 브로드캐스트, `127.0.0.1` 세 갈래로 나간다.
어댑터에 따라 `255.255.255.255` 로 나간 패킷이 조용히 버려지는 경우가 있고, 루프백은 같은 PC
경로를 보장한다.

## 코드 알파벳

`ABCDEFGHJKMNPQRSTUVWXYZ23456789` (31자). 음성으로 불러 주고 손으로 받아 적는 물건이라
`I/1/L`, `O/0` 을 통째로 뺐다. 발급 쪽이 애초에 쓰지 않으므로, 옮겨 적기가 맞다면 검증은 항상
통과한다. 틀리면 조용히 고쳐 주는 대신 "6자리가 아니다" 라고 말한다.

## 포트

| 용도 | 포트 | 비고 |
| --- | --- | --- |
| 게임(UTP) | UDP 7979 | `LastShiftNetworkSession.DefaultPort` |
| 방 코드 디스커버리 | UDP 7980 | `LastShiftRoomProtocol.DiscoveryPort` |

방화벽에서 두 포트 모두 인바운드 UDP 를 열어야 한다. 디스커버리만 막히면 코드 검색이 실패하고,
게임 포트만 막히면 코드는 찾지만 접속에서 멈춘다 — 로비가 두 경우를 다른 문구로 구분한다.

## 한계 (의도한 것)

- **같은 LAN 안에서만** 코드가 통한다. 인터넷 너머는 여전히 IP 직접 접속이거나, 나중에 Relay 다.
- 한 PC 에 방은 하나. 디스커버리 포트를 못 잡으면 방은 열리되 코드 검색이 꺼지고, 로비가 그
  사실을 화면에 적는다(IP 를 아는 상대는 여전히 들어올 수 있다).
- 코드는 인증이 아니다. 같은 LAN 에서 코드를 아는 사람은 누구나 들어온다. 정원 4인 초과는
  기존 `ApproveConnection` 이 거절하고, 로비가 그 사유를 그대로 보여 준다.

## 기존 경로와의 관계

`-lastShiftNetworkMode host|client` 커맨드라인 경로는 그대로다. 자동화(`LastShiftNetworkLifecycleProbe`,
PlayMode 테스트)가 계속 쓴다.

바뀐 것은 **인자 없이 켰을 때** 하나다. 예전에는 바로 host 가 떴고, 이제는 로비가 열린다.
`LastShiftNetworkSession.AutoStartHost = false` 로 두면 예전처럼 로비도 자동 host 도 없다 —
테스트가 쓰는 그 의미 그대로다.

## 수동 확인

1. 에디터 Play → 로비 → `방 열기` → 우상단에 코드가 뜨고 승무원이 스폰된다.
2. 같은 PC 또는 같은 LAN 의 다른 PC 에서 Player 빌드 실행 → 코드 입력 → `입장` → 두 번째
   승무원이 호스트 화면에 나타난다.
3. 없는 코드를 넣으면 4초 뒤 "찾지 못했습니다" 가 뜨고 로비로 돌아갈 수 있다.
