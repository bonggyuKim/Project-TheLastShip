# NAN 2026 AI 게임 개발 워크플로 운영 근거

> 상태: 제출 검토용 측정 메모 · 기준일 `2026-08-10`  
> 대상: AgentDesk의 `bonggyuKim/Project-DoodleUp` 저장소 카드 중 제목이 `[LAST SHIFT]`로 시작하는 작업  
> 재현 도구: `docs/tools/measure_nan2026_ai_workflow.ps1`

## 1. 실측 결과

AgentDesk의 카드와 디스패치 API를 읽기 전용으로 조회했다. 카드 생성부터 완료까지의 전체 시간과 실제 구현 디스패치 구간을 구분했다.

| 항목 | 표본 | 중앙값 | 25~75% 구간 | 90% 지점 | 해석 |
|---|---:|---:|---:|---:|---|
| 카드 lead time | 완료 카드 89건 | 19.2분 | 12.1~30.2분 | 60.2분 | 카드 생성부터 완료 시각까지의 wall-clock |
| 카드 작업 구간 | 시작·완료 시각이 있는 카드 88건 | 17.8분 | 11.4~26.2분 | 38.1분 | 시작부터 완료까지이며 대기·도구 실행을 포함 |
| 구현 디스패치 구간 | 완료된 구현 실행 93건 | 16.9분 | 10.5~24.4분 | 30.5분 | 구현 요청 생성부터 완료까지의 wall-clock |

운영 표본에는 완료 카드 89건, 완료된 구현 디스패치 93건, 완료된 phase gate 55건이 포함됐다. 전체 표본 기간은 `2026-08-03`부터 `2026-08-10`까지다.

평균 lead time은 75.4분이지만 최댓값 3,744.5분인 장기 체류 카드의 영향을 크게 받는다. 대표값은 평균보다 중앙값과 분위수를 우선한다.

## 2. 재작업 해석

정식 `review_round`가 1회 이상 기록된 완료 카드는 0건이었다. 따라서 현재 데이터만으로는 `QA 반려 카드 수 / 완료 카드 수`를 사실로 제시할 수 없다.

대신 완료 카드 중 구현 디스패치 시도가 두 번 이상 발생한 카드는 10건으로, 완료 카드 대비 11.2%다. 여기에는 완료·실패·취소된 시도가 함께 포함된다. 이 값은 보완·재실행 가능성을 보여 주는 **동일 카드 재실행 프록시**이며 QA 반려율이나 결함률로 해석하지 않는다.

## 3. 아직 수치화할 수 없는 항목

| 항목 | 현재 판단 | 필요한 추가 기록 |
|---|---|---|
| AI active time | 카드·디스패치 wall-clock과 분리 불가 | 모델 실행, tool 대기, queue 대기를 분리한 turn lifecycle |
| 인간 개입 시간 | 승인·방향 수정 사건은 남지만 소요시간 필드가 없음 | 플레이 검토·아트 승인·방향 수정의 시작·종료 시각 |
| 모델·API 비용 | provider 사용량이 카드와 직접 연결되지 않고 청구 비용 필드가 없음 | card/dispatch ID가 붙은 토큰 사용량과 실제 청구 단가·비용 |
| 검증 자동화 절감 | 자동 검증 시간은 남지만 동일 범위 수동 baseline이 없음 | 같은 테스트 묶음의 수동 검증 시간 표본 |
| 산출물 채택률 | 카드와 main 병합은 추적되지만 AI 제안 단위가 정의되지 않음 | 제안·수락·수정·기각 단위를 고정한 ledger |

측정되지 않은 값을 시간 절감률이나 비용 절감률로 환산하지 않는다.

## 4. 재현 절차

AgentDesk 로컬 서버와 설정이 있는 Windows 환경에서 실행한다. 스크립트는 인증값을 출력하지 않으며 카드·디스패치 API를 읽기만 한다.

```powershell
powershell -ExecutionPolicy Bypass -File docs/tools/measure_nan2026_ai_workflow.ps1
```

결과 JSON의 `card_lead_time_minutes`, `implementation_dispatch_window_minutes`, `pipeline_evidence`를 이 문서와 대조한다. 제출 직전 다시 실행해 표본 수와 기준 시각을 갱신한다.
