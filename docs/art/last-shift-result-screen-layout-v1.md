# LAST SHIFT 결과 화면 — 레이아웃·타이포 (v1)

> **⚠ 아카이브 (`2026-08-10`).** 도킹 판정·도킹 결과 카드는 현재 게임 구조에서 폐기됐다. 이 문서는 색·타이포 참고만 가능하며 화면 목적과 카피의 정본이 아니다. 새 결과 UI는 함선 누적 변화·손상·자원·저장 상태를 중심으로 `docking-removal-persistent-ship-save-v1.md` §6-3에서 다시 결정한다.

`docs/game-feel-loop-review-v1.md` §3.1 `G-1`의 아트 몫. 기능(판정 `5`종 · 원인 줄 · 요약 `4`칸 · 다음 판 입력)은 `game-tech-director`가 구현하고, **이 문서는 그것이 화면에서 어떤 크기·색·순서로 읽히는지를 고정한다.** 톤 기준은 `docs/art/last-shift-art-style-guide-v1.md`(로우폴리 + "가볍고 유쾌한 협동").

목업: `docs/art/mockups/last-shift-result-*.png` — 이 문서의 좌표표를 그대로 그린 것이고, 재생성은 `python Tools/art/render_result_screen_mockup.py`.

## 1. 결론 먼저

- **씬 전환이 아니라 딤 + 중앙 카드.** 판이 끝난 배가 뒤에 남아 있어야 "우리가 한 판"이 결과와 같은 화면에 있다. 검은 화면으로 덮으면 방금까지의 우당탕이 지워진다
- **위계는 `3`단뿐이다** — 판정 `64px` → 원인 `28px` → 요약 `4`칸 `36px`. 지금 `OnGUI`는 `20/14` 두 단이라 결과 화면이 HUD와 같은 무게로 읽히면 안 된다
- **색은 성공/실패 `2`갈래로만 나눈다.** 실패 `3`종을 색으로 쪼개면 매 판 새 색을 배우게 된다 — `3`종 구분은 칩(`산소`/`도킹`/`추력`)과 원인 줄이 한다
- **결과 화면은 HUD 등급색 점멸을 쓰지 않는다.** 점멸은 "지금 급하다"는 신호인데 여기서는 급할 게 없다

## 2. 화면 골격

```
┌────────────────────────── 딤 68% (게임 화면 그대로 비침) ──────────────────────────┐
│                                                                                  │
│              ▔▔▔▔▔▔▔▔▔▔ 판정색 밴드 14px ▔▔▔▔▔▔▔▔▔▔                              │
│              [칩]                                                                 │
│              판정 큰 줄            64                                             │
│              원인 줄              28                                              │
│              ───────────────────────────────────────                             │
│              라벨 20   라벨      라벨      라벨                                    │
│              값 36     값        값        값                                     │
│              ───────────────────────────────────────                             │
│              다음 판 — [키]        24                                             │
│                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- 카드는 화면 정중앙이 아니라 **세로 중심에서 `50px` 위**(카드 중심 `y=480`, 화면 중심 `540`)에 둔다. 아래에 배가 보이는 여백을 남기는 배치이고, 눈이 위에서 아래로 읽어 내려가 마지막에 배로 떨어진다
- 카드 안은 **좌측 정렬 한 열.** 중앙 정렬을 쓰지 않는 이유는 원인 줄 길이가 판정마다 `4`자~`30`자로 크게 달라서, 중앙 정렬이면 매 판 글줄 시작점이 움직인다
- **판정별로 카드 높이를 바꾸지 않는다.** 정상 도킹은 원인 줄이 비지만 자리는 그대로 둔다 — 성공에는 설명할 실패가 없고, **그 여백 자체가 "아무 일도 없었다"는 정보다**

## 3. 팔레트

스타일 가이드 §2(명도 하한 = 무채색 검정 금지, 채도 하한 = 포스터컬러)를 그대로 적용했다. 딤 색이 검정이 아니라 짙은 청람인 것이 그 규칙의 직접 결과다.

| 역할 | 값 | 비고 |
|---|---|---|
| 딤 오버레이 | `#0E1A2B` · `68%` | 검정 금지. 게임 화면이 실루엣으로 남는 농도 |
| 카드 바탕 | `#1A2E48` | 불투명 |
| 구분선 | `#304C6D` | `1px` |
| 라벨 | `#8FA6BF` | 요약 `4`칸 라벨 |
| 값 | `#FFFFFF` | 요약 값 |
| 값(`0`) | `#6E8299` | `0`이면 낮춘다 — "안 쓴 것"은 조용해야 한다 |
| 원인 줄 | `#D8E4F2` | |
| 하단 입력 줄 | `#9FB4CC` | |
| 성공(정상) | `#4FD8A0` | 신규 |
| 성공(절충) | `#FFDB59` | HUD `불안정` 등급색 `(1.00,0.86,0.35)` 재사용 |
| 실패 `3`종 | `#FF5A4D` | HUD `위기` 적색의 채도 상향판. **결과 화면에서는 점멸 없음** |
| 칩 바탕 | 판정색 `18%` + 카드 바탕 | 칩 글자는 판정색 |

**도킹 진척 셀만 값 색 규칙이 다르다 — 항상 판정색으로 칠한다.** `150/150`이면 성공색이라 성공 화면에서 한 칸이 밝게 남고, 미달이면 실패색이라 표류 화면에서 왜 졌는지가 요약 칸에서 한 번 더 보인다. 규칙이 하나라 구현 분기도 하나다.

## 4. 좌표·타이포 (`1920×1080` 기준)

`OnGUI`는 절대 픽셀이라 이 표를 그대로 `Rect`에 넣을 수 있다. **단 다른 해상도에서 카드가 화면 비율을 잃으므로** 전체를 한 번 감싼다:

```
var s = Mathf.Min(Screen.width / 1920f, Screen.height / 1080f);
GUIUtility.ScaleAroundPivot(Vector2.one * s, Vector2.zero);   // 그린 뒤 matrix 복원
```

지금 HUD 패널(`16,16,680,262`)도 같은 문제를 갖고 있지만 그건 이 카드 범위 밖이다.

| 요소 | Rect (x, y, w, h) | 폰트 | 색 |
|---|---|---|---|
| 딤 | `0, 0, 1920, 1080` | — | 딤 `68%` |
| 카드 | `400, 250, 1120, 460` | — | 카드 바탕 |
| 상단 밴드 | `400, 250, 1120, 14` | — | 판정색 |
| 칩 | `440, 286, 텍스트+28, 34` | `22` Bold | 칩 바탕/판정색 |
| 판정 큰 줄 | `440, 326, 1040, 84` | `64` Regular | 판정색 |
| 원인 줄 | `440, 428, 1040, 40` | `28` Regular | `#D8E4F2` |
| 구분선 ① | `440, 502, 1040, 1` | — | `#304C6D` |
| 요약 라벨 `i` | `440+260i, 526, 260, 26` | `20` Regular | `#8FA6BF` |
| 요약 값 `i` | `440+260i, 552, 260, 48` | `36` Bold | §3 규칙 |
| 구분선 ② | `440, 622, 1040, 1` | — | `#304C6D` |
| 다음 판 줄 | `440, 646, 1040, 34` | `24` Regular | `#9FB4CC` |

- 내부 여백 `40px` 고정, 요약 칸 폭 `260px` × `4` = 내부 폭 `1040px`에 정확히 맞는다
- **칸 사이 세로 구분선은 넣지 않는다.** 가로선 `2`개로 이미 묶여 있고, 격자가 더 늘면 정산표처럼 무거워진다

## 5. 판정 `5`종 — 칩·색·카피

카피는 `G-1` 표를 그대로 쓴다(새 용어 금지). art가 더한 것은 **칩**뿐이고, 칩 어휘도 화면에 이미 있는 계통 이름에서만 골랐다.

| 판정 | 칩 | 큰 줄 | 원인 줄 | 색 |
|---|---|---|---|---|
| `SuccessNominalDocking` | `도킹` | 정상 도킹 | (빈 줄, 자리 유지) | `#4FD8A0` |
| `SuccessCompromised` | `도킹` | 절충 생환 | 포기한 계통 `N`개 | `#FFDB59` |
| `FailureAsphyxiation` | `산소` | 질식 | `○○실` 산소 고갈 · 예비 산소 소진 | `#FF5A4D` |
| `FailureAdrift` | `도킹` | 표류 | 도킹 진척 `138`/`150` — 추력이 `5`분 평균 `0.46`이었다 | `#FF5A4D` |
| `FailureInsufficientThrust` | `추력` | 추력 부족 | 도착 시점 추력 `0.25` (엔진 보호 잠금 `N`초) | `#FF5A4D` |

- 원인 줄 안의 숫자는 `richText`로 흰색 `<b>`를 줘도 좋다(선택). 폰트 폴백이 굵기를 합성하는 환경에서는 색만 올리는 쪽이 안전하다
- 요약 `4`칸 라벨은 `CT-01` §5.5 문장 그대로: `포기한 것` · `임시 수리` · `재이탈` · `도킹 진척`

## 6. 폰트 — 지금 상태와 권고

프로젝트에 폰트 에셋이 하나도 없다(`.ttf`/`.otf` `0`개). 지금 한글은 `GUI.skin.label` 기본 폰트가 OS 폴백으로 그리는 것이라 **실제로 어떤 서체가 나오는지가 실행하는 PC에 달려 있다.** HUD의 `14~20px`에서는 티가 안 났지만 `64px`에서는 바로 보인다.

- **당장:** 판정 큰 줄을 `Bold`가 아니라 `Regular`로 둔다. 폴백이 굵기를 합성하면 큰 글자에서 획이 뭉친다 — 위계는 크기(`64` vs `28`)와 색으로 이미 충분히 선다. `Bold`는 `36px` 요약 값과 `22px` 칩까지만
- **후속(별도 카드 권고):** 한글 포함 폰트 하나를 번들한다. 결과 화면은 매 판 마지막에 `5`초 이상 보는 유일한 화면이라 임시 UI가 가장 크게 티 나는 자리다(`game-feel-loop-review-v1.md` §4-4가 예고한 아트 부채가 정확히 여기다)

## 7. 모션 — art 의견, 타이밍은 tech 확정

톤이 "가볍고 유쾌한 협동"이라 결과 화면도 무겁게 내려앉으면 안 된다. 총 `0.8`초 안에 다 끝난다.

| 시각 | 동작 |
|---|---|
| `0.00–0.15s` | 딤 페이드 인 |
| `0.10–0.30s` | 카드가 아래에서 `24px` 올라오며 페이드 (ease-out) |
| `0.30–0.42s` | 판정 큰 줄 팝 (스케일 `1.06` → `1.00`) |
| `0.45–0.75s` | 요약 `4`칸이 좌→우 `0.06s` 간격으로 페이드 인 |
| `0.80s` | 다음 판 줄 등장 |

- **다음 판 입력은 줄이 보이는 `0.80s`부터 받는다.** 보이지 않는 입력을 먼저 받으면 결과를 못 읽고 넘어간 판이 생긴다
- 값 카운트업은 넣지 않는다 — 세는 값이 `0~3` 범위라 카운트업이 성립하지 않는다

## 8. HUD·국소정보 규칙과의 관계

- **결과 화면이 뜨면 기존 HUD 패널(`16,16,680,262`)은 숨긴다.** 판정 후 시뮬레이션이 멎어 있어서 막대가 살아 있는 값처럼 오독된다. `F3` 디버그 층은 그대로 둔다(QA 도구)
- **결과 화면에는 정확한 수치를 적어도 된다.** `CT-01` §5.2가 수치를 가둔 것은 "가야 안다"는 런 중 규칙이고, 판이 끝난 뒤에는 가둘 대상이 없다. 결과 화면은 이 게임에서 **숫자가 허용되는 유일한 플레이어 화면**이라는 것을 명시해 둔다 — 이 예외가 없으면 다음 사람이 §5.2를 근거로 원인 줄의 `138/150`을 지운다
