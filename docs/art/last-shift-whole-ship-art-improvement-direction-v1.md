## 0. 결론 먼저

현재 배는 방의 위치와 기능 소품은 존재하지만, 화면에서는 **바닥 접지 결함**, **큰 무정보 암면**, **전경 차폐**, **같은 바닥·천장 모듈의 반복**, **방별 주인공 실루엣과 조명 레이어의 부재**가 먼저 읽힌다. 특히 전력실 캐비닛, 냉각실 박스, 생명유지실 실린더, 조종석 좌석이 모두 가는 봉 위에 떠 보이는 현상은 네 방에 걸친 공통 신호다. 개별 방 배치보다 공통 마운트·피벗·프리팹 생성 규칙을 먼저 의심한다.

가장 먼저 손댈 대상은 다음과 같다.

1. **측정 기준:** 방마다 두 개 이상의 비교 가능한 검수 숏을 먼저 확보하고 캡처 버전을 분리한다.
2. **공통 접지:** 네 방에서 반복되는 부유 형상의 단일 원인을 확인한다.
3. **조종석:** 베이지 전면 패널의 크기·위치를 조정해 관측창을 드러내고 전방 축을 회복한다.
4. **숙소:** 침상과 커튼을 하나의 명확한 생활 모듈로 만든다.
5. **광장/EVA 리프트:** 코어의 기존 오목 패널과 수평 밴드가 보이도록 명도 위계를 세우고 EVA 축을 구분한다.
6. **공통 조명:** 무정보 암면을 줄이되 배 전체를 관통하는 붉은 바닥 라인은 통합 조형 언어로 보존한다.
7. **화물:** 현 증거로는 판정을 보류하고 재캡처 후 진단한다.

## 1. 화면 문제를 세 종류로 나눈다

| 구분 | 판별 기준 | 필요한 수정 | 코드 변경 |
|---|---|---|---|
| **검수 캡처 앵글 문제** | 캡처 카메라만 대형 소품 사이 또는 벽 바로 앞에 있고, 다른 시점에서는 공간이 보인다 | 검수 카메라 위치·높이·주시점과 방별 대표 숏 재정의 | **필요.** 자동 캡처 위치·주시점·샷 목록은 Editor 코드 변경 |
| **실제 플레이 카메라 문제** | 정상 플레이 중 플레이어 눈높이·FOV에서 기능물, 출입구, 이동 방향이 계속 가려진다 | 플레이 카메라 FOV·클리핑·추적 방식, 투명화 또는 차폐 처리 검토 | **조건부 필요.** 카메라 동작과 런타임 차폐 처리는 코드 |
| **배치·지오메트리 결함** | 서로 다른 각도의 캡처 **2장 이상**에서 같은 가림·부유·관통·실루엣 붕괴가 반복된다 | 피벗·마운트·스케일·메시·정적 배치 수정 | art/데이터 우선. 기능물 위치나 생성 규칙이면 코드·테스트 필요 |

현재 증거만으로 플레이 카메라 문제라고 확정할 수 있는 영역은 없다. **서로 다른 각도 2장 이상에서 반복되면 카메라 문제로 돌리지 않고 배치·지오메트리 결함으로 분류한다.** 네 방의 공통 접지 결함과 숙소 침상 실루엣은 이 기준의 우선 확인 대상이다. 반면 화물과 EVA 리프트의 현행 캡처는 카메라가 대형 형상에 지나치게 가까워 검수 앵글 문제임이 명확하다.

검수 증거 폴더에는 천장 버그 수정 전·후 이미지가 섞여 있다. 이후 캡처는 파일명 또는 폴더에 **커밋/리베이크 버전과 천장 수정 상태**를 스탬프해 비교 대상을 분리한다. 버전이 확인되지 않는 기존 이미지는 구조 참고용으로만 쓰고 전후 판정 증거로 사용하지 않는다.

## 2. 방별 개선 브리프

### 2.1 중앙 광장

**시급한 문제**

1. 중앙 코어의 크기보다 **명도 부족**이 문제다. 두 대각 캡처에서 출입구는 보이지만, 코어의 기존 오목 패널과 수평 밴드가 암면에 묻혀 단색 직육면체처럼 보인다.
2. 바닥·천장·벽의 반복 모듈과 교차하는 보·레일이 많지만, 어느 면이 어느 방으로 이어지는지 알려 주는 랜드마크와 조명 위계가 없다.

**인상을 가장 크게 바꾸는 한 가지:** 새 형상을 늘리기 전에 코어의 기존 오목 패널과 수평 밴드가 읽히도록 면광·반사·중간명도를 조정한다. 이후 면별 라벨과 제한된 색 스트립으로 방향을 구분한다.

**화면 문제 판정:** 두 대각 캡처에서 출입구가 모두 확인되므로 현재 증거만으로 코어 크기나 플레이 차폐 결함을 판정하지 않는다. 반복 확인되는 것은 **명도·표면 위계 결함**이다.

**코드 의존성:** 코어 표면과 조명·표지는 art 작업. 자동 캡처 재구성은 Editor 코드 필요. 플레이 중 차폐 투명화나 카메라 조정이 필요하면 런타임 코드 필요.

### 2.2 조종석

**시급한 문제**

1. 큰 검은 측벽과 베이지 전면 패널, 작은 좌우 콘솔이 분리되어 보여 전방 관측과 조종이라는 하나의 주인공 구도가 생기지 않는다. 특히 **베이지 패널 두 장이 전면 관측창을 거의 가린다.**
2. 중앙 암색 좌석은 가는 봉 위에 떠 보이며, 좌우 장비의 크기와 명도 차가 약해 조종석보다 가구가 놓인 빈 방처럼 보인다.

**인상을 가장 크게 바꾸는 한 가지:** 베이지 전면 패널 두 장을 축소하거나 측면으로 이동해 관측창을 먼저 드러낸다. 그 뒤 전면 관측면·주 콘솔·좌석을 하나의 축으로 묶는다.

**카메라 판정:** 중앙 좌석이 정면을 막는 것은 현행 정면 **검수 앵글 문제**일 수 있다. 실제 플레이 시작 시점에도 관측면과 출구가 동시에 안 읽히면 플레이 카메라 문제로 승격한다.

**코드 의존성:** 모델·배치·조명은 art/데이터. 스폰 방향, 플레이 카메라 시작 구도, 자동 캡처는 코드 필요.

### 2.3 전력실

**시급한 문제**

1. 중앙 암색 캐비닛은 화면의 약 15%를 차지하고 좌우 공간도 보이지만, 가는 봉 위에 떠 보여 바닥 접지가 깨진다. 녹색 점 세 개 외에는 조작면 정보가 약하다.
2. 좌측 전경의 주황 상자가 프레임 최고채도 물체라 주 설비보다 먼저 읽히는 **색 위계 역전**이 있다. 우측 배전 요소는 암면에 묻힌다.

**인상을 가장 크게 바꾸는 한 가지:** 중앙 설비의 조작면을 밝기·형태·케이블 흐름으로 전면화한다. 캐비닛 몸체보다 사람이 접근하는 면이 먼저 읽혀야 한다.

**화면 문제 판정:** 캐비닛이 방 대부분을 가린다는 진단은 철회한다. 접지 결함은 다른 방에서도 반복되므로 **공통 배치·지오메트리 결함 후보**다. 주황 상자의 색 위계는 현 캡처에서 확인되는 아트 구성 문제다.

**코드 의존성:** 설비 외형·표면·정적 조명은 art. 상호작용 위치나 접근 방향을 바꾸면 게임플레이 데이터/코드 검토 필요. 캡처 수정은 Editor 코드 필요.

### 2.4 냉각실

**시급한 문제**

1. 중앙 밝은 사각 설비와 좌측 대형 직육면체가 가는 지지 봉 위에 떠 보이고, 전경 원통까지 한 축에 겹쳐 깊이와 작업 순서가 끊긴다.
2. 우측 청록 라디에이터 외에는 방을 구분하는 형태 언어가 약하고, 설비 대부분이 기본 프리미티브처럼 보인다.

**인상을 가장 크게 바꾸는 한 가지:** 냉각의 흐름이 보이는 주 설비 라인을 만든다. 라디에이터·배관·밸브·캐니스터가 한 방향성 있는 묶음으로 연결되면 방의 기능이 즉시 읽힌다.

**카메라 판정:** 좌측 대형 형상이 프레임 밖으로 잘리고 전경 캐니스터가 중앙 설비와 겹치는 것은 우선 **검수 앵글 문제**다. 실제 조작 시 밸브와 게이지 또는 캐니스터가 서로 가리면 플레이 배치 문제다.

**코드 의존성:** 외형·배관·조명은 art. 기능물의 위치·접근 관계를 바꾸면 게임플레이 데이터 및 테스트 변경 가능. 캡처 수정은 Editor 코드 필요.

### 2.5 생명유지실

**시급한 문제**

1. 키 큰 탱크와 실린더가 앞·중간·뒤에 반복되고 가는 봉 위에 떠 보인다. 우측 대형 판재까지 겹쳐 시야가 여러 번 끊긴다.
2. 민트·시안 발광 요소는 많지만 무엇이 주 설비인지 밝기와 실루엣의 우선순위가 없다.

**인상을 가장 크게 바꾸는 한 가지:** 생명유지 코어 하나를 주인공으로 정하고, 나머지 탱크와 배관이 그 코어를 보조하도록 높이와 명도를 계층화한다.

**카메라 판정:** 우측 전경 판과 반복 기둥의 겹침은 현행 **검수 앵글 문제**가 크다. 플레이어가 방을 이동할 때도 출구와 기능물이 연속적으로 가려지면 배치/플레이 카메라 문제다.

**코드 의존성:** 정적 소품·조명은 art. 기능물 재배치는 데이터 및 상호작용 테스트 검토 필요. 런타임 차폐가 필요하면 코드 필요.

### 2.6 숙소

**시급한 문제**

1. 침상은 낮고 긴 회갈색 판재와 레일로, 커튼은 분리된 갈색 판으로 보여 서로 연결된 수면 공간으로 읽히지 않는다.
2. 넓고 빈 중앙 테이블과 대칭 벤치가 방의 시각 중심을 차지해, 숙소보다 회의실 또는 식당 인상을 만든다. 로커도 검은 세로 상자처럼 보인다.

**인상을 가장 크게 바꾸는 한 가지:** **침상+커튼 통합 모듈**을 먼저 완성한다. 2단 구조, 매트리스·베개, 사다리·손잡이, 커튼 레일과 반개방 천, 개인 독서등이 한 실루엣 안에 있어야 한다.

3.0m 실내고는 유지할 수 있다. 문제는 높이보다 굵고 긴 중앙 빔과 단일 평면 조명 때문에 천장이 무겁게 내려앉아 보이는 것이다. 중앙등과 침상별 개인광을 나누고, 테이블은 축소 또는 시각 비중을 낮춘다. 로커는 4인 단위가 보이도록 문과 표식을 분절한다.

**카메라 판정:** 현행 역방향 캡처는 검은 벽과 근경 가구에 일부 가리지만, 테이블이 침상을 압도하고 침상 실루엣이 약한 문제는 여러 각도에서 반복되어 **아트 구성 문제**다. 실제 플레이 카메라 문제로 볼 근거는 아직 없다.

**코드 의존성:** 침상·커튼·테이블·로커·조명은 art. 상호작용 없는 정적 드레싱이면 코드 불필요. 자동 캡처 개선만 Editor 코드 필요.

### 2.7 화물 소품군

**판정 상태: 보류.** 현행 한 장은 대형 프롭 사이에 카메라가 끼어 있어 공간과 적재 상태를 판정할 수 없다. 재캡처 전에는 아래 내용을 개선 처방으로 확정하지 않는다.

**재캡처에서 확인할 문제**

1. 현행 캡처는 검은 대형 프롭과 밝은 대형 프롭 사이에 끼어 바닥 접촉, 적재 방식, 통로 폭이 보이지 않는다.
2. 별도 화물실이 아니라 냉각실 쪽 적재 소품군인데, 캡처 이름과 구도가 독립 화물실처럼 오해를 만든다. 적재의 규칙과 고박 관계도 화면에서 드러나지 않는다.

**다음 한 가지:** 전체 적재 묶음, 바닥 접촉, 통로가 동시에 보이는 검수 숏을 먼저 만든다. 적재물·팔레트·고박 장치의 개선안은 그 캡처를 본 뒤 정한다.

**카메라 판정:** 현재 가장 명확한 **검수 캡처 앵글 문제**다. 이 캡처만으로 플레이 카메라 문제를 판단하면 안 된다.

**코드 의존성:** 적재 묶음은 art/데이터. 자동 캡처 이름·위치·주시점 변경은 Editor 코드 필요. 적재물이 게임플레이 이동물이라면 콜라이더와 상호작용 검토 필요.

### 2.8 EVA 상부와 리프트

**시급한 문제**

1. 외부 상면에서 해치와 주변 선체의 명도·형태가 비슷하고, 지지대·보·레일이 분리되어 떠 있는 듯 보여 해치와 선체의 연결 구조가 약하다.
2. 리프트 내부에서는 중앙 암색 벽이 화면 대부분을 막아 승강 입구, 이동 방향, 주변 광장의 관계가 보이지 않는다.

**인상을 가장 크게 바꾸는 한 가지:** 해치-리프트-광장을 잇는 하나의 수직 랜드마크를 확립한다. 해치 테두리, 승강문, 방향광이 같은 형태 언어와 제한된 강조색을 공유해야 한다.

**카메라 판정:** 리프트 내부 캡처는 중앙 벽에 너무 가까운 **검수 앵글 문제**다. 실제 승강 중 카메라도 같은 벽을 응시하거나 구조 내부에 박히면 플레이 카메라/시네머신 문제다. 외부 상면의 구조 연결 부족은 카메라와 별개의 아트 문제다.

**코드 의존성:** 해치·리프트 외형과 정적 조명은 art. 승강 중 카메라 전환, 벽 투명화, 동적 해치 상태는 런타임 코드 필요. 자동 검수 숏은 Editor 코드 필요.

## 3. 공통 조형 언어와 공통 결함

### 3.1 접지 결함

조종석 좌석, 전력실 캐비닛, 냉각실 박스, 생명유지실 실린더가 모두 가는 봉 위에 떠 보인다. 네 방의 독립 배치 실수로 나누지 않고 **공통 마운트·피벗·bottomY·프리팹 생성 규칙의 단일 원인**을 먼저 확인한다. 서로 다른 각도에서도 바닥 간격이 유지되면 배치·지오메트리 결함으로 확정한다.

**코드 의존성:** 원인이 메시 피벗이나 프리팹 Visual 계층이면 art/TA, 공통 생성·배치 규칙이면 Editor 코드와 재리베이크, 기능물 높이가 바뀌면 관련 테스트 검토가 필요하다.

### 3.2 붉은 바닥 라인

배 전체 벽 하단을 관통하는 붉은 라인은 방들을 한 우주선으로 묶는 현재의 가장 명확한 통합 조형 언어다. 개별 소품이 라인과 겹쳐 묻히는 문제는 소품 위치·명도에서 해결하고, 라인 자체를 방별로 제거하거나 색을 분산하지 않는다. 위험·동선·선체 결을 연결하는 공통 자산으로 유지한다.

### 3.3 조명과 무정보 암면

코어 오목 패널, 수평 밴드, 벽 프레임처럼 이미 존재하는 형상이 검은 면에 묻혀 있다. 신규 디테일을 추가하기 전에 중간명도, 림, 국부 작업광으로 기존 형상을 복원한다. 방별 고유색은 주 기능 설비와 입구에 제한하고, 붉은 바닥 라인은 공통 기준색으로 남긴다.

## 4. 전체 우선순위

| 순위 | 작업 묶음 | 기대 효과 | 코드 의존성 |
|---:|---|---|---|
| 1 | 검수 카메라·증거 버전 재설계 | 다른 모든 판정의 측정 기준 확보. 방별 2각도 이상과 버그 수정 상태 스탬프 | **Editor 코드 필요** |
| 2 | 공통 접지 결함 원인 확인·수정 | 네 방에 반복되는 부유 형상을 한 번에 제거 | 원인에 따라 art/TA 또는 Editor 코드·테스트 |
| 3 | 공통 조명·중간명도 패스 | 무정보 암면을 줄이고 이미 있는 패널·밴드·프레임 복원 | TA 협업, 구현 방식에 따라 코드 조건부 |
| 4 | 조종석 베이지 패널 축소/이동 + 전방 관측 축 | 첫 인상과 선수 방향성을 빠르게 회복 | 배치는 art/데이터, 스폰/카메라는 조건부 코드 |
| 5 | 숙소 침상+커튼 통합 모듈 | 숙소 정체성을 즉시 회복 | 기본적으로 없음 |
| 6 | 광장 코어/EVA 수직 랜드마크 | 코어의 기존 형상과 EVA 목적지를 명료화 | 정적 아트는 없음, 동적 카메라는 조건부 필요 |
| 7 | 전력·냉각·생명유지 주 설비 실루엣 정리 | 방별 기능 구분과 작업면 가독성 향상 | 기능물 이동 시 데이터/테스트 필요 |
| 보류 | 화물 소품군 | 재캡처 후 진단 | 캡처는 Editor 코드 필요 |

## 5. 실행 전 수동 확인

사용자 승인 후 실행 카드를 만들기 전에 실제 Play Mode에서 다음만 분리 확인한다.

- 방별로 서로 다른 각도 2장 이상을 확보했고 같은 커밋·리베이크·천장 수정 상태인가.
- 네 방의 좌석·캐비닛·박스·실린더가 다른 각도에서도 바닥에서 같은 방식으로 뜨는가.
- 플레이어 기본 눈높이와 FOV에서 광장 코어가 실제로 출입구를 가리는가, 아니면 표면 명도만 부족한가.
- 전력·냉각·생명유지 기능물에 접근할 때 다른 기능물과 출구가 계속 보이는가.
- 숙소 진입 시 첫 시선에서 침상, 테이블, 로커 중 무엇이 가장 먼저 읽히는가.
- EVA 승강 중 카메라가 구조물 안으로 들어가거나 암면만 바라보는 구간이 있는가.
- 화물 소품군 전체와 바닥 접촉을 한 화면에 담을 수 있는 검수 시점이 있는가.

이 확인 전에는 정지 캡처의 가림을 전부 플레이 카메라 결함으로 기록하지 않는다.
