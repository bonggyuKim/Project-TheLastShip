# LAST SHIFT — 캐릭터 전신 충돌 변형 런타임 설계 v1

game-art 핸드오프(2026-08-18)에 대한 game-tech-director 회신. 대상은 라임 외계인 승무원,
런타임은 Unity Built-in RP(`m_CustomRenderPipeline: 0`), 물리 50Hz(`Fixed Timestep 0.02`).

## 0. 먼저 — 래그돌은 이미 있다

Blender에서 시험한 13 물리체/12 관절은 **Unity에 이미 구현돼 있다.**
`LastShiftRagdollRig.Bones` 가 12 파트(Pelvis/Spine/Chest/Head/UpperArm·Forearm L·R/Thigh·Shin L·R),
`LastShiftRagdoll.Build` 이 Rigidbody 12 + 관절 11(볼 `CharacterJoint`, 무릎·팔꿈치 `HingeJoint`)을
세운다. 질량비·관절 한계·정지 판정·`ApplyImpulse`/`ApplyBlast` 까지 있고 한계 초과는 2.06배 →
1.27배로 잡혀 있다.

**그래서 래그돌을 `ConfigurableJoint` 로 다시 만들지 않는다.** 무릎·팔꿈치를 볼 조인트로 두면
스윙 콘을 85°×10°로 찌그러뜨려야 하는데 PhysX가 그 비율에서 한계를 못 지킨다 — 솔버를 32/8까지
올려도 2.06→1.80배였고, 힌지로 바꿔서야 175°→90°로 정확히 걸렸다. `ConfigurableJoint` 는 같은
스윙 콘 방식이라 이 문제를 되돌린다.

`ConfigurableJoint` 가 필요한 경우는 하나뿐이다 — **관절 자체에 스프링 복원(드라이브)을 걸어
"맞고 나서 자세를 되찾는" 반능동 래그돌**을 원할 때. 그때도 볼 관절(어깨·고관절·척추·목)만
바꾸고 무릎·팔꿈치는 힌지로 둔다. 이건 기획이 원하는지부터 정해야 할 사안이라 이 설계의
필수 경로에는 넣지 않았다.

**남은 절반은 국소 변형이다.** 아래는 그 설계다.

## 1. 구조 — 두 층으로 나눈다

접촉 하나가 **두 곳으로 동시에** 간다.

```
충돌(Collider 접촉)
   ├─→ [물리층]  Rigidbody.AddForce(impulse)      ← 이미 있음. 전신이 흔들린다.
   └─→ [표현층]  접촉 레코드 → 셰이더 변형 버퍼   ← 신규. 그 자리가 눌린다.
```

두 층은 서로 안 읽는다. 표현층이 죽어도 물리는 그대로고, 물리가 잠들어도(`IsSettled`)
눌린 자국은 스스로 복원된다. 이 분리가 중요한 이유는 멀티 때문이다 — **변형은 순수 시각이라
복제하지 않는다.** 임펄스는 이미 호스트 권위로 복제되고, 각 클라이언트가 자기 화면에서
같은 접촉으로 같은 변형을 만든다. 변형을 복제하면 승무원 4인분 대역폭이 이유 없이 든다.

## 2. 표현층을 보조본이 아니라 정점 변위로 하는 이유

세 가지를 놓고 골랐다.

| 안 | 방식 | 판정 |
|---|---|---|
| A. 보조본 | 파트마다 헬퍼 본 N개, 스프링 복원 | **탈락** |
| B. 정점 변위 | 접촉 버퍼 → 정점 셰이더 커널 | **채택** |
| C. 저해상도 볼륨 솔버 | 파트별 격자 + 부피 구속 | **탈락** |

**A가 탈락한 이유는 웨이트 예산이다.** 이 메시는 이미 4본 상한에 붙어 있다 — game-ta 계측으로
5,772 정점 중 **2,576개가 이미 4본**이고 임포트 설정도 `maxBonesPerVertex=4` 다. 보조본을 넣으려면
8본으로 올리고(스키닝 비용 약 2배) **전 정점 웨이트를 다시 칠해야 한다.** 그 작업이 바로 지난주
메시 찢어짐 카드(`#9c1eda6b`)를 만든 작업이다. 같은 함정을 다시 판다.

**C가 탈락한 이유는 art가 Blender에서 이미 부딪힌 그 벽이다.** 부피 구속을 제대로 걸려면
파트별 격자 + Jobs/Burst 솔버 + 매 프레임 메시 쓰기(`SetVertices`)가 필요하고, 승무원 4인분
정점 업로드가 프레임 예산을 먹는다. 4인 co-op 프로토타입이 감당할 구조가 아니다.

**B는 뼈도 웨이트도 안 건드린다.** 메시가 한 장이든 여섯 장이든 그대로 동작한다 —
이 캐릭터는 통짜 ↔ 셸 분리를 이미 두 번 오갔으므로 이게 실질적인 이점이다.
Built-in RP라 Surface Shader(`#pragma surface surf Standard vertex:vert`)로 쓰면 Standard 조명을
그대로 유지한다.

**B의 한계도 적어 둔다: 콜라이더는 안 변한다.** 눌린 자국으로 다른 물체가 파고들지는 않는다.
물리적 반응은 래그돌이 전담한다는 것이 이 설계의 전제다. 이걸 뒤집으려면 C뿐이다.

## 3. 커널 — 눌림과 부피 보존

접촉 하나는 파트 로컬 공간의 레코드다: 위치 `p`, 법선 `n`, 반경 `r`, 깊이 `d`.

정점 `v`에 대해 거리 `t = |v - p| / r` 일 때

```
dent  = -n * d * W(t)                     W(t) = (1 - t²)²      , t ≤ 1
bulge = +normal(v) * d * k * B(t)         B(t) = t²(1 - t)² * c
```

`W` 는 눌림, `B` 는 그 둘레의 불룩함이다. `k` 는 커널 위에서 적분한 `∫W` 와 `∫B` 가 같아지도록
한 번 풀어 상수로 박는다 — 그러면 눌린 만큼 옆으로 밀려나 **부피가 근사 보존**된다.
Blender Soft Body에 부피 보존이 없어 액체처럼 흐른 것이 이 항이 없어서다.

법선은 커널의 해석적 기울기로 셰이더 안에서 다시 만든다(정점 법선을 그대로 쓰면 눌린 면의
음영이 안 따라온다).

**커널 정의는 한 곳에만 둔다.** HLSL과 C#에 같은 식을 두 벌 적으면 반드시 갈린다.
C# 쪽(`LastShiftBodyDeformKernel`)을 정본으로 두고 셰이더는 그 상수를 받아 쓰며, 아래 검증
기준의 부피 검사는 C# 미러로 헤드리스에서 돈다.

## 4. 스프링 감쇠 — 정점이 아니라 접촉 하나당 스칼라

정점마다 물리를 돌리지 않는다. **레코드 하나가 깊이 스칼라 `d` 하나를 갖고**, 그것만 감쇠
진동한다.

```
d̈ = -ω²(d - d_target) - 2ζω ḋ
```

접촉 중에는 `d_target` = 침투 깊이, 접촉이 끝나면 0으로 떨어진다. `ζ < 1` 로 두면 한 번
출렁이고 돌아오는 살 같은 느낌이 나온다. 승무원 하나당 슬롯 8개면 스칼라 8개다.

## 5. 성능 예산

| 항목 | 4인 기준 | 비고 |
|---|---|---|
| 래그돌 물리 | Rigidbody 48 / 관절 44 | **현재와 동일**, 늘지 않는다 |
| 접촉 스프링 | 스칼라 32개 | CPU 무시 가능 |
| 정점 커널 | 5,772 v × 8 슬롯 × 4인 ≈ 185k 평가/프레임 | GPU 무시 가능 |
| 스키닝 | **변화 없음** | 본 수·본/정점 그대로 |
| 메시 업로드 | **없음** | 정점을 CPU에서 안 쓴다 |

목표: 표현층 CPU **≤ 0.3 ms**(4인), 물리 비용은 오늘 측정값에서 증가 0.

## 6. 구현 단계

각 단계는 **다음 단계 없이도 검증 가능**하게 잘랐다.

1. **접촉 수집** — 래그돌 콜라이더 홀더(`{Part}__RagdollCollider`)에 접촉 릴레이를 붙여
   월드 접촉점을 파트 로컬로 바꾸고, 임펄스는 기존 `ApplyImpulse` 로, 레코드는 버퍼로 보낸다.
   *렌더링 없음. 여기까지 헤드리스로 끝난다.*
2. **커널 + 스프링** — `LastShiftBodyDeformKernel` 과 슬롯 버퍼. C# 미러로 부피·복원을 잰다.
   *여전히 렌더링 없음.*
3. **셰이더** — Surface Shader 정점 변위, 슬롯 8개를 `MaterialPropertyBlock` 벡터 배열로 전달.
   *여기서 처음 화면이 필요하다.*
4. **튜닝** — `ω`, `ζ`, `r`, `k` 를 실제 플레이에서 맞춘다. **사용자 판정 사항.**

## 7. 검증 기준

| 항목 | 기준 | 방법 |
|---|---|---|
| 접촉→파트 매핑 | 12 파트 전부 정확 | EditMode |
| 부피 보존 | 최대 눌림에서 `|ΔV|/V < 2%` | EditMode, C# 커널 미러 |
| 탄성 복원 | 0.4초 내 피크의 5% 이하, 가시 오버슈트 ≤ 1회 | EditMode, 스칼라만 |
| 래그돌 무영향 | `LastShiftRagdollLimitCheck` 결과 불변 | 기존 검사 재실행 |
| 성능 | 표현층 ≤ 0.3 ms / 4인 | 프로파일러 |
| 화면 | 눌림·불룩함·음영이 접촉 위치를 따라감 | 캡처 1장(3단계) |

## 8. art에게 필요한 것 / 필요 없는 것

**필요 없다 — 이게 B를 고른 가장 큰 이유다.**
- 보조본 추가 없음
- 웨이트 재작업 없음
- 메시 재분할/병합 없음

**필요하다.**
- 몸 머티리얼이 신규 셰이더를 쓰도록 교체(3단계에서 tech가 하되, 룩 판정은 art)
- 파트별 기본 눌림 반경 `r` 의 감각적 기준값(머리는 크게, 정강이는 작게)

**주의.** 현재 Assets에 임포트된 FBX는 아직 6장 셸 버전이고
(`RagdollShell_Torso/Head/Arm_L/Arm_R/Leg_L/Leg_R`), art의 새 원본
`LastShiftLimeAlien_FinalRig_Weighted.blend` 는 단일 스킨 메시다. 이 설계는 둘 다 지원하지만,
**재임포트하면 프리팹의 몸 렌더러 링크가 다시 끊긴다** — 그건 `LastShiftNetworkPlayerLinkRepair`
가 임포트 직후에 자동으로 잇는다(`86c1743`). 재임포트 후 `unity test --mode EditMode` 로
`LastShiftGhostTests` 와 네트워크 검증만 한 번 확인하면 된다.
