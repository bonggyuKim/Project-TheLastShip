> 상태: `game-planning` 검토안 v1 · `2026-08-08` · 카드 `6a08d952-4db0-4596-aab8-4f1216db32f9` (사용자 직접 지시)
> 상위 정본: `voyage-run-structure-v1.md`(항해·구간·기항) · `rg1-1-measurement-definition-v1.md`(`RG-1(1)`·`W-1` 조문) · `bow-cockpit-central-plaza-layout-v1.md`(기본 배 도안)
> 실측 기준: `LastShiftCompartments.cs` · `LastShiftZonePressure.cs` · `LastShiftRg1GuardrailTests.cs` · `DoodleUp.Editor.asmdef` (전부 이번 검토에서 직접 읽었다)
> **산출물은 타당성 평가 + 방향 제안이다. 구현이 아니고, 좌표를 하나도 안 바꾼다.**

## 0. 결론 먼저

1. **채택 권고한다. 다만 "실시간"이라는 말이 이 카드에서 두 가지를 가리키고 있고, 둘 중 하나는 필요 없다.** 안전성 판정은 **매 프레임 도는 것이 아니라 배치를 확정하려는 순간 한 번** 돌면 된다. 배치는 기항(판 밖)에서만 일어나기 때문이다(§3.1). 이 구분이 이번 검토의 실질 이득이다 — 매 tick 검증이면 압력 시뮬 루프 안으로 들어가야 하지만, 배치 시점 검증이면 **판 안 코드를 한 줄도 안 건드린다.**

2. **RG-1 계산 자체는 관문이 아니다. 싸다.** 구획 `11`개, 부모 사슬 깊이 최대 `4`, `EgressMeters` 는 사슬을 한 번 거슬러 올라가는 덧셈이다. 확장 모듈이 `20`개로 늘어도 전 구획 이탈 재계산이 산술 수백 회, `W-1`(구역 내 최장 쌍)이 `O(N²)` 로 수백 회다. **커서를 움직일 때마다 돌려도 부담이 없다.** "엔진 구조상 실현 가능한가"의 답은 계산에 있지 않다.

3. **진짜 관문은 지오메트리다. 그리고 그것은 코드 구조 문제가 아니라 자산 문제다.** `LastShiftSceneBuilder`(`2,240`줄)·`LastShiftDressingSeed`(`719`줄)가 `DoodleUp.Editor.asmdef`(`"includePlatforms": ["Editor"]`)에 들어 있다. **런타임에 방을 세우는 경로가 이 프로젝트에 없다** — `Scripts/Runtime` 전체에서 오브젝트를 만드는 자리는 `Du03BCPlayabilityVisuals` 하나뿐이고 LastShift 와 무관하다. 그래서 §4 는 절차적 생성이 아니라 **모듈 프리팹 조립**을 권고한다.

4. **"어디에든 붙인다"는 유지한다. 대신 자유는 위치에 주고 형태에는 안 준다.** 격자 `1m` 스냅, 회전 `90°` 4단계, 방 도형은 카탈로그 고정. 사용자가 확인한 것은 "자리 자체를 임의로 정한다"이고 그것은 위치의 자유다. 45° 회전 하나가 문 평면(`AlongX`/`AlongZ`)·`AABB` 겹침 검사·드레싱 배치 규칙·시선차단 계산을 전부 깬다(§3.3).

5. **안전성 위반은 원천 차단하지 않는다. 3층으로 나누고, 가드레일 층은 숫자만 보여주고 짓게 둔다.** 근거는 셋이다 — (가) 사용자가 "이상해져도 괜찮다"고 명시했다, (나) `RG-1` 은 원래 **기획자가 지켜서 플레이어가 안 겪게 하는 약속**인데 자유 배치의 요점이 그 약속의 주체를 플레이어로 옮기는 것이다, (다) **위반의 대가가 이미 시뮬레이션 안에 있다.** `RG-1(1)` 을 넘긴 배는 실제로 그 구석에서 사람이 죽는다. 인공 페널티를 얹으면 이중 처벌이다(§5).

6. **가장 얇은 가드레일(`RG-1(3)` 부피비, 여유 `1.07배`)이 자유 배치에 대해 무력하다 — 이게 이번 검토의 가장 중요한 발견이다.** 판정 대상이 압력 구역 `4`개의 x 길이인데(`corridor-4p-redesign-v1.md` §24), 자유 배치가 늘리는 것은 부속 구획이고 부속은 `ZonePressure` 슬롯을 안 만든다. **방을 `100`개 붙여도 판정값은 `2.80배` 그대로다.** 조문을 실 기밀 체적 기준으로 다시 써야 자유 배치가 처음으로 이 항목에 걸린다(§6).

7. **기본 시작 배로 선수 조종석 + 중앙 광장 도안을 쓰는 방향은 맞다. 조건 셋이 붙는다.** (a) 확장 모듈은 원반 **밖**에 붙는다 — 원반은 이미 내접 여유가 에어록 `0.758m` 까지 차 있다, (b) 큰 방 둘(격납고·화물칸, 각 `80m²`)을 시작 배에서 빼서 카탈로그로 내린다, (c) 도안 §7-7 사용자 확인 셋(특히 원반 `84m → 48m`)이 자유 배치보다 먼저 닫혀야 한다 — "붙일 수 있는 밖"의 기준선이 원반 테두리이기 때문이다(§7).

8. **P1 항해 구조와 궁합이 좋다. 세이브가 여전히 필요 없다.** 배치는 항해 안에서만 누적되고 항해가 끝나면 배가 새것으로 돌아간다(`voyage-run-structure-v1.md` §0-1). **"매 판 배 모양이 달라진다"가 저장 백본 없이 성립한다.**

## 1. 용어 — 여기서 고정한다

`voyage-run-structure-v1.md` §1 의 셋(구간 / 기항 / 항해)을 그대로 쓰고, 이 문서가 넷을 더한다.

| 용어 | 정의 |
|---|---|
| **압력 스파인** | 조종석 · 전력실 · 냉각실 · 산소실 방과 그 사이 통로. `ZonePressure` 슬롯 `4`개를 갖는 본선이다 |
| **확장 모듈** | 자유 배치로 붙이는 부속 구획 하나. `LastShiftCompartmentSpec` 한 줄에 대응한다 |

## 2. 실측 — 지금 구조가 자유 배치에 대해 무엇인가

### 2.1 구획표는 정적 배열 하나다

```csharp
// LastShiftCompartments.cs:162
private static readonly LastShiftCompartmentSpec[] specs = BuildSpecs();
```

`BuildSpecs()` 가 `Count = 11` 개를 한 번 만들고 끝난다. 씬 빌더·검증기·테스트가 **전부 여기서 파생한다**(`:134` 주석이 명시). 자유 배치는 이 배열을 **런타임 가변 목록**으로 바꾸는 일이고, 그러면 파생처가 통째로 따라온다. **이게 tech 작업량의 뿌리이지 RG-1 계산이 아니다.**

다행인 것은 자료 구조가 이미 맞다는 점이다. `LastShiftCompartmentSpec` 은 `(x범위, z범위, 문평면, 문좌표, ParentIndex, Access)` 뿐이고 좌표가 리터럴이 아니라 **"무엇에 붙어 있는지"로 적혀 있다**(`:140` 주석). 자유 배치가 요구하는 표현력이 이미 이 구조체 안에 있다.

### 2.2 구역 소속을 x 하나가 정한다 — 자유 배치에서 이게 무너진다

```csharp
// LastShiftZonePressure.cs:74  Resolve
for (var boundary = 0; boundary < BoundaryCount; boundary++)
    if (position.x <= BoundaryPlanes[boundary]) return (LastShiftZone)boundary;
return (LastShiftZone)(ZoneCount - 1);
```

지금은 맞다. 부속 구획이 전부 자기 부모 방과 x 가 겹치도록 배치돼 있기 때문이다. **자유 배치가 되면 즉시 틀린다** — 조종석 사슬에 붙었지만 `x = +20` 으로 뻗어 나간 모듈은 x 로 재면 산소실 구역이 되고, **조종석 문을 닫아도 격리가 안 된다.**

**고치는 방법은 좁다.** `Resolve` 를 "점이 어느 확장 모듈 `AABB` 안에 있으면 그 모듈의 구역, 아니면 기존 x 판정"으로 바꾼다. 모듈의 구역은 배치 확정 시 사슬 뿌리에서 한 번 정해 캐시한다. **점–AABB 검사 `N`회 + 기존 분기**이므로 매 tick 돌아도 싸고, `ZoneCount = 4` 는 안 건드린다.

> **조항 F-1.** 확장 모듈의 압력 구역은 **배치 시점에 사슬 뿌리로 결정되고 이후 안 바뀐다.** 좌표로 다시 재지 않는다 — 재면 모듈 하나를 옮길 때 이웃 모듈의 구역이 조용히 바뀐다.

### 2.3 압력 구역 `4`개는 자유 배치 대상이 아니다

**확장 모듈은 전부 부속 구획이고, 압력문을 새로 만들지 않는다.** 근거 셋.

1. **`ZoneCount = 4` 에 걸려 있는 것이 많다.** `LastShiftZonePressures` 배열, `SIMUL_ZONES ≤ 2`, `RG-4` 파공 구역 조합, HUD 칸 수, 네트워크 스냅샷. 구역이 가변이 되면 이 다섯이 동시에 열린다.
2. **재미상으로도 구역이 고정이어야 결정이 선다.** "어느 구역 쪽에 방을 몰아 붙일까"가 결정이 되려면 구역이 셈의 단위여야 한다. 구역까지 자유면 그 결정 자체가 사라진다.
3. **카드가 요청한 것은 "자리의 자유"이지 "구역의 자유"가 아니다.** 압력문 배치는 §9 에 P2 후보로 남긴다.

### 2.4 `RG-1(1)` 여유가 이미 거의 없다 — 이게 자유 배치의 실제 제약이다

```text
                    최악 이탈    판정 시간    한도까지 남은 보행 거리
현행 배 (관측실)     30.61m      8.45초       6.19m
도안   (산소실)      29.64m      8.21초       7.16m     ((10 − 0.8) × 4 − 29.64)
```

**시작 배에서 최악 사슬 끝에 이을 수 있는 거리가 `7.16m` 다.** 카탈로그에서 가장 작은 축에 드는 방(화장실 `2m` · 관측실 `3m`)이라도 사슬 끝에 붙이면 자기 깊이만큼 이탈이 늘어나므로, **연장은 한두 개면 끝난다.**

**반대로 분기는 거의 공짜다.** `rg1-recalc-voyage-port-unlock-v1.md` §2.2 가 확인한 대로 기항 개방 셋이 안전했던 이유가 전부 "분기이지 연장이 아니다" 하나였다. 즉 자유 배치의 안전성은 **어디에 붙이느냐가 아니라 무엇에 붙이느냐**로 갈린다.

> **이 사실이 §5 배치 미리보기의 설계 근거 전부다.** 플레이어에게 "여기는 안 됩니다"를 말할 게 아니라 **"이 자리는 최악 이탈을 `+3.2초` 늘립니다"** 를 보여줘야 한다. 그러면 플레이어가 연장과 분기를 스스로 구분하게 된다.

### 2.5 부피비는 자유 배치를 안 막는다

`RG-1(3)` 은 세 가드레일 중 여유가 가장 얇은데(`2.80배` / 한도 `3`, 여유 `1.07배`), **판정 대상이 압력 구역의 x 길이라 부속 구획을 아무리 붙여도 안 움직인다.** 실제로 도안이 큰 방 둘을 선미로 옮겼을 때도 판정값은 불변이었고 **부속 체적 래칫만 `8.46 → 12.05`, `9.21 → 12.55` 로 깨졌다**(도안 §3.2).

그리고 지금 압력 시뮬은 체적을 안 쓴다 — `Equalize()`(`LastShiftZonePressure.cs:333`)는 차이의 고정 비율만큼 접근시키는 상수 모델이다. **부피비는 현재 순수한 서류상 가드레일이고, 자유 배치는 그 서류가 재는 것과 다른 축으로 자란다.** §6 이 이걸 다룬다.

## 3. 배치 규칙 제안

### 3.1 언제 배치하는가 — 기항에서만

| 항목 | 값 | 근거 |
|---|---|---|
| 배치 시점 | **기항 화면. 구간 중에는 불가** | 구간 중 지오메트리 변경은 압력 시뮬·네트워크 동기화·드레싱을 통째로 연다. `5`분 실시간 압박과도 안 맞는다 |
| 배치 비용 | 정비 여력 `1` (기존 세 계열에 **배치**를 넷째로 추가) | `voyage-run-structure-v1.md` §4.2 문법 재사용 |
| 되돌리기 | **같은 기항 안에서는 무료로 철거·재배치. 출항하면 확정** | 미리보기 숫자를 보고 고치는 것이 이 시스템의 학습 경로 전부다 |
| 지속 | 이번 항해 동안. 항해 종료 시 리셋 | §0-8 |

**기존 "개방" 계열과의 관계.** 지금 `voyage-run-structure-v1.md` §4.2 의 개방은 "잠긴 방을 연다"인데, 그 방들은 좌표가 미리 정해져 있다. **자유 배치가 들어오면 개방과 배치가 같은 것이 된다** — 방을 산다는 것은 곧 자리를 정한다는 뜻이다. 두 계열을 합치고 "개방"이라는 이름을 **배치**로 바꾸는 것을 권고한다. 용어가 하나 줄고, `LastShiftCompartmentAccess.Locked` 가 "지어져 있는데 안 열림"에서 "아직 안 지음"으로 의미가 정돈된다.

### 3.2 어디에 붙일 수 있는가

| 규칙 | 내용 |
|---|---|
| **격자** | `1m` 스냅. 문 폭 `1.6m` 가 격자에 안 떨어지므로 문은 접면 중앙 고정이고 격자 대상이 아니다 |
| **회전** | `90°` 4단계. 자유 회전 없음(§3.3) |
| **접면 조건** | 기존 구조물(스파인 방 · 이미 놓인 모듈)의 한 면과 **`1.6m` 이상 맞닿아야** 한다. 그 접면에 문이 하나 뚫린다 |
| **부모** | 접면 상대가 곧 `ParentIndex`. **모듈마다 정확히 하나** — 기존 "막다른 방" 전제 유지 |
| **겹침** | 기존 `VolumesOverlap` 그대로. 열린 구간 비교라 공유 벽은 겹침이 아니다 |
| **원반** | 확장 모듈은 원반 **밖**에 놓인다. 원반 안은 시작 배가 이미 다 쓴다(§7) |

### 3.3 왜 자유 회전을 기각하는가

깨지는 것이 넷이다. **하나씩 다 실물 근거가 있다.**

1. **문 평면.** `LastShiftDoorPlane` 은 `AlongX`/`AlongZ` 둘뿐이고, `DoorSitsOnOwnBoundary`(`:318`)가 그 전제 위에 서 있다. 45° 문은 이 검사가 아예 정의되지 않는다.
2. **겹침 검사.** `VolumesOverlap` 은 `AABB` 구간 비교다. 회전 사각형 겹침은 SAT 로 새로 짜야 하고, 그 순간 `153` 쌍 검사가 전부 새 코드가 된다.
3. **드레싱.** `LastShiftDressingRules` 가 벽면·바닥 좌표 규칙으로 물건을 놓는다. 축 정렬이 아니면 규칙이 안 선다.
4. **시선차단.** 배플 논증(도안 §3.1)이 "두 개구부를 잇는 직선 집합"의 선형 보간 위에 서 있고, 그 보간이 축 평행일 때만 폭이 일정하다.

**그리고 플레이어 이득이 거의 없다.** 45° 로 붙은 방이 주는 것은 실루엣 다양성 하나인데, 그건 모듈 종류와 배치 조합으로 이미 충분히 나온다. **비용 대비가 가장 나쁜 항목이라 여기서 명시적으로 기각한다.**

### 3.4 루프를 허용할 것인가 — 조건부 허용

플레이어는 고리형 배를 만들고 싶어 한다. 그게 자연스럽다. 그런데 `ParentIndex` 단일 부모가 지키고 있는 것이 둘 있다 — "막다른 방" 전제(`:104` 주석)와 **갑판 하부 우회로가 유일한 유료 대안 경로라는 것**(도안 §4 불변식 4).

> **조항 F-2.** 확장 모듈끼리의 루프는 **허용한다.** 단 그 루프가 **압력 구역 경계를 가로지르면 안 된다.**

같은 구역 안에서 도는 고리는 `SuitOxygen` 비용을 우회하지 못하므로(같은 구역이라 애초에 안 깎인다) 무해하고, 동선 다양성만 준다. 구역을 가로지르는 고리는 그 순간 압력문 없는 구역 간 경로가 생겨 **`SIMUL_ZONES`·격리·우회로 비용이 동시에 죽는다.**

**구현상으로는 `ParentIndex` 를 그대로 두고 "부모가 아닌 접면"을 추가 통로로 따로 들면 된다.** 부모 사슬은 여전히 트리라 `DoorDepth`·`EgressMeters` 가 안 깨지고, 추가 통로는 이탈 시간을 **줄이는** 방향으로만 작용하므로 `RG-1(1)` 판정을 보수적으로 유지한다.

### 3.5 방 카탈로그

**P1 시작 카탈로그는 `6`종을 권고한다.** 근거는 산수다 — 기항 `2`회 × 여력 `2~3` 이므로 한 항해에 놓는 모듈이 `4~6`개다. 카탈로그가 그보다 훨씬 크면 첫 항해에 대부분을 못 보고, 훨씬 작으면 매 항해 같은 배가 나온다.

| 모듈 | 발자국 | 붙는 이유 (플레이어 동기) |
|---|---|---|
| 수경재배·산소재생실 | `6×6` | 산소 시계를 늦춘다 |
| 서버/통신실 | `4×6` | 조기 경보 |
| 의무실 | `4×5` | 개인 상태 회복 |
| 정비창 | `3×5` | 자재를 만든다 |
| 화물칸 | `8×8` | 예비 자재 · 예비 배터리 |
| 격납고 | `8×10` | 큰 방. 실루엣이 눈에 띄게 바뀌는 유일한 항목 |

**셋(수경재배·서버/통신실·의무실)은 이미 `Locked` 로 지어져 있고 기항 개방 목록과 같다.** 즉 카탈로그의 절반이 신규 제작이 아니라 **좌표 해제**다. 정비창·화물칸·격납고는 시작 배에서 빼서 내리는 것이라 역시 신규 제작이 아니다(§7-b). **P1 카탈로그의 art 신규 비용은 사실상 `0` 이고, 비용은 전부 "붙는 자리에 문틀을 세우는" 쪽에 있다.**

## 4. 지오메트리 — 절차적 생성이 아니라 프리팹 조립

**§0-3 이 확인한 대로 런타임에 방을 세우는 경로가 없다.** 선택지는 둘이다.

| | (가) 런타임 절차 생성 | (나) 모듈 프리팹 조립 |
|---|---|---|
| 내용 | `LastShiftSceneBuilder` 를 Editor → Runtime 으로 이관 | 모듈 종류마다 완성 프리팹 하나. 배치는 `Instantiate` + 접면에 문틀 프리팹 |
| 방 형태 | 임의 크기 가능 | **카탈로그 고정** |
| 드레싱 | 절차적으로 채워야 한다 — 미해결 문제 | **프리팹 안에 이미 들어 있다** |
| 코드량 | `2,240` + `719`줄 이관 + Editor 의존 제거 | 배치기 하나 + 문틀 규칙 |
| art 비용 | 배치 수에 비례 | **모듈 종류 수에 비례** |

**권고는 (나)다.** §3.2 가 방 도형을 카탈로그로 고정했으므로 절차적 생성이 필요 없고, 드레싱이 프리팹 안에 들어가면 "드레싱을 절차적으로 채우는" 미해결 문제 자체가 안 생긴다.

**그래서 §3.3(자유 회전 기각)과 §4(프리팹 조립)는 같은 결정의 양면이다.** 형태의 자유를 포기한 대가로 지오메트리 비용이 배치 수에서 종류 수로 내려온다. 자유는 **어디에 놓는가**에 남고, 그게 카드가 요청한 자유다.

## 5. 안전성 판정 — 3층

> **L0 · 물리적 불가 → 차단한다.** 겹침, 접면 미달(`< 1.6m`), 부모 없음, 시작 배 원반 침범. **이유: 씬이 안 닫힌다.** 회색 상자가 서로를 파고들거나 문틀이 허공에 뜬다.
>
> **L1 · 시스템 불변식 → 차단한다.** 압력 구역 경계를 가로지르는 루프(F-2), 복구 항목(배전반 · 산소실 밸브)이 스파인에서 도달 불가능해지는 배치. **이유: 시뮬레이션이 정의되지 않거나, `RG-3`(영구 잠금 금지)이 깨진다.**
>
> **L2 · 가드레일 → 차단하지 않는다.** `RG-1(1)`·`(2)`·`(4-b)`·`W-1`. **숫자를 보여주고 짓게 둔다.**

### 5.1 L2 를 왜 안 막는가

1. **사용자가 명시적으로 확인했다** — "자기가 확장한거고 구조를 짠거니까 괜찮지".
2. **`RG-1` 의 주체가 바뀌는 것이 이 시스템의 요점이다.** 지금까지 `RG-1` 은 기획자가 지켜서 플레이어가 안 겪게 하는 약속이었다. 자유 배치는 배의 모양을 플레이어에게 넘기는 것이고, 그러면 그 약속도 같이 넘어간다. **차단하면 넘긴 것이 아니다.**
3. **페널티를 따로 만들 필요가 없다 — 대가가 이미 시뮬 안에 있다.** `RG-1(1)` 한도 `10초` 는 `SuitOxygen 80초` 의 `12.5%` 에서 나온 값이고, 그것을 넘긴 배는 **실제로 그 구석에서 사람이 죽는다.** 위반 시 추가 페널티를 얹는 것은 이중 처벌이고, 무엇보다 "왜 졌는지"를 흐린다.

### 5.2 배치 미리보기에 무엇을 띄우는가

**숫자 셋 + 변화량.** 등급·색 그라데이션을 안 쓴다.

```text
  최장 이탈    8.21초 →  11.4초   (한도 10초)   ← 넘김
  최악 복구   33.2초  →  33.2초   (한도 40초)
  최장 동선    9.81초 →   9.81초  (권고 10초)
```

**게이지 판독 `3`단 문법과 안 섞는다.** 판독 `3`단은 판 안의 거리 규칙이고 배치 화면은 판 밖이라 `SIMUL_ZONES` 대상이 아니다(`voyage-run-structure-v1.md` §7). 여기서는 숫자를 그냥 다 보여주는 것이 맞다.

**한도를 넘겨도 배치 버튼은 살아 있다.** 대신 확정할 때 한 번 더 묻고, 그 문구가 결과를 사실로 적어야 한다 — "이 방 안쪽 구석에서 진공이 나면 승무원이 나오기 전에 죽습니다" 같은 식이다(문안은 `game-writer`).

## 6. `RG-1(3)` 조문 개정 제안 — 부피비를 실 기밀 체적으로

**§2.5 가 확인한 대로 지금 부피비는 자유 배치를 하나도 안 막는다.** 그런데 이게 조문의 취지대로면 막아야 한다 — 부피비가 재려던 것은 "한 구역이 다른 구역보다 지나치게 크면 재가압·감압 체감이 안 맞는다"이고, **방을 한 구역에 몰아 붙이는 것이 정확히 그 상황이다.**

> **개정안.** `RG-1(3)` 의 판정 대상을 압력 구역의 x 길이에서 **그 구역이 실제로 안고 있는 기밀 체적**(스파인 구간 + 그 구역에 편입된 확장 모듈 전부)으로 바꾼다. 한도 `3배` 는 유지 후보이되 `game-balance` 재산정 대상이다.

**얻는 것.** 자유 배치가 처음으로 부피비에 걸린다. 그리고 그 규칙이 플레이어에게 물리로 읽힌다 — **"산소실 쪽에만 방을 몰아 붙이면 그 구역 재가압이 느려진다."** 인공 규칙이 아니다.

**비용이 둘 있다.** (가) 부속 체적 래칫 둘(`12.1`·`12.6`)이 판정값으로 승격되면서 **현재 도안이 즉시 위반이 될 수 있다** — 재산정 없이 이 개정을 적용하면 안 된다. (나) 체감을 만들려면 `Equalize()` 에 체적 항이 들어가야 하는데(§2.5), 지금은 상수 모델이라 **압력 시뮬을 여는 유일한 항목**이다. **그래서 §9 에 별건으로 뗀다** — 조문 개정은 판정만 바꾸는 것으로 먼저 하고, 체감 반영은 `game-balance` 가 값을 낸 뒤다.

## 7. 기본 시작 배 — 도안을 그대로 쓰는가

**쓴다. 조건 셋.**

**(a) 확장 모듈은 원반 밖에 붙는다.** 도안 §8.1 실측으로 원반(`a=24`, `b=22`, 중심 `x=+7`) 안 발자국 `18`개가 전부 내접인데 **최빡빡이 에어록 `0.758m`** 다. 요구선이 `0.4m` 이므로 남은 여유가 `0.36m` — **원반 안에는 방 하나 들어갈 자리가 없다.** 확장부를 원반 밖으로 보내면 `LastShiftHullShell` 재파라미터화가 불필요해지고, 시각적으로도 "원래 배 + 붙여 나간 것"이 한눈에 갈린다. 이게 `modular-docking-progression-review-v1.md` §4.3-(나) 해체 편입과도 맞물린다 — **붙인 것이 곧 떼어질 것이다.**

**(b) 큰 방 둘을 시작 배에서 뺀다.** 격납고(`80m²`)·화물칸(`80m²`)을 카탈로그로 내린다. 근거 둘 — 안 빼면 시작 배가 이미 꽉 차서 붙일 동기가 안 생기고, 도안 §5 가 좌현 점유율 여유를 **`6.2%p`** 로 적어 두었는데 이 둘이 그 여유를 먹고 있다. **빼면 §5 판정 기준 중 좌현 점유율(`36.2%`, 기준 `30%`)과 `z` 중심 치우침(`+2.0`, 한도 `±2.5`)을 다시 재야 한다** — 격납고가 `z +10~+18` 로 치우침의 주범이므로 빼면 좋아지는 방향이지만, 좌현 점유율은 나빠질 수 있다. `game-tech-director` 재실행 대상이다.

**(c) 도안 §7-7 사용자 확인 셋이 먼저 닫혀야 한다.** 특히 원반 `84m → 48m`. **자유 배치는 "붙일 수 있는 밖"의 기준선을 원반 테두리로 삼으므로, 원반 크기가 안 정해지면 배치 규칙 자체가 안 선다.** 이게 이 카드의 유일한 선행 차단 항목이다.

## 8. 플레이어가 실제로 겪는 것

**사례 A — 첫 배치.** 구간 `1`에서 산소가 계속 모자랐다. 기항 화면에서 여력 `2` 중 `1`을 써서 수경재배를 집는다. 커서를 산소실 방 우현 벽에 대면 접면이 초록으로 붙고 미리보기에 `최장 이탈 8.21 → 8.21초`(안 변함)가 뜬다. 확정. **분기라서 공짜였다는 것을 숫자로 봤다.**

**사례 B — 연장의 대가.** 같은 기항에서 남은 `1`로 격납고를 집는다. 수경재배 바깥쪽 벽에 붙이려니 `최장 이탈 8.21 → 12.6초 (한도 10초)` 가 뜬다. 커서를 산소실 방 반대편으로 옮기면 `8.21 → 8.21초`. **"방 뒤에 방을 붙이면 안 된다"를 아무도 말해 주지 않았는데 플레이어가 두 번 움직여 보고 알았다.**

**사례 C — 알면서 짓는다.** 격납고를 굳이 수경재배 뒤에 붙인다. 배 실루엣이 한쪽으로 길게 뻗어 마음에 든다. 경고를 읽고 확정한다. 구간 `2`에서 산소실 파공. 격납고에 있던 승무원이 뛰어나오는데 `SuitOxygen` 이 문 앞에서 끊긴다. **졌는데 왜 졌는지가 명확하다 — 자기가 지은 자리다.**

**사례 D — 4인.** 기항 화면에서 넷이 갈린다. 조종석 담당은 서버/통신실을 광장에 붙이자고 하고(조기 경보), 산소실 담당은 수경재배를 민다. 미리보기 숫자가 화면에 떠 있으므로 **논쟁이 취향이 아니라 숫자를 두고 벌어진다.** `voyage-run-structure-v1.md` §6-E 가 만든 첫 합의 자리가 여기서 한 단계 구체적이 된다.

**사례 E — 두 번째 항해.** `R` 을 누르면 배가 도안 그대로 새것이다. 지난 항해에 만든 이상한 실루엣은 사라졌다. **그런데 이번엔 격납고를 먼저 붙여 보고 싶다.** 재플레이 동기가 `voyage-run-structure-v1.md` §8-7 이 "얇다"고 적어 둔 자리에서 처음 생긴다.

| `SIMUL_ZONES ≤ 2` | **재실행 필요** | 확장 모듈에서 게이지 둘이 동시에 보이는 배치가 나올 수 있다. **다만 모듈이 원반 밖이고 게이지는 개구부 `1`·`3` 에 있으므로 위반 가능성은 낮다** — `game-tech-director` 확인 |
| `RG-4` 파공 구역 조합 | **의미가 바뀐다** | 같은 조합이라도 그 구역에 무엇을 붙였느냐로 무게가 달라진다. 수치는 그대로 |
| 시선차단 `A3` · 게이지 판독 `3`단 | **없음** | 확장 모듈이 개구부·배플·게이지 좌표를 안 건드린다 |

**가장 얇은 지점은 `W-1` 이다.** `RG-1(1)` 은 `1.22배` 남았는데 `W-1` 은 권고선까지 `0.19초` 다. 그리고 `W-1` 은 한도가 없는 관측 항목이라 **아무것도 안 막는다.** 자유 배치가 들어오면 이 값이 실제 체감 한계가 되므로, **`W-1` 을 배치 미리보기의 셋째 숫자로 올리는 것**이 §5.2 의 설계다 — 판정으로 만들지 않으면서 플레이어에게는 보이게 하는 유일한 방법이다.

## 10. 트레이드오프와 비용

1. **`Resolve()` 를 고치는 것이 압력 시뮬의 심장을 건드린다.** §2.2 의 방법은 좁지만 그래도 구역 판정 함수다. 여기가 틀리면 문을 닫아도 격리가 안 되는 배가 나오고, 그건 이 게임의 모든 결정이 통하는 자리다. **`game-tech-director` 가 가장 먼저 봐야 할 항목이다.**
2. **`LastShiftCompartments` 가 정적 배열에서 가변 목록이 되면서 파생처가 전부 따라온다.** 씬 빌더·검증기·EditMode 테스트 다수. 테스트는 "현재 배의 좌표"를 고정하고 있는데 배가 가변이 되면 **무엇을 고정할지부터 다시 정해야 한다** — 값이 아니라 불변식을 고정하는 쪽으로 성격이 바뀐다.
3. **모듈 프리팹 방식은 방 형태의 자유를 영구히 포기한다.** 나중에 "방 크기를 늘리고 싶다"가 나오면 (가)로 되돌아가야 하고, 그때는 이미 프리팹 `6`개에 드레싱이 들어가 있다. **되돌리기 비용이 있는 결정이라 명시한다.**
4. **`RG-1(3)` 개정은 현재 도안을 즉시 위반으로 만들 수 있다.** §6-(가). 재산정 없이 적용 금지.
5. **배치 미리보기가 새 UI 다.** 지금 UI 는 전부 `OnGUI` 즉시 모드이고, 기항 화면 자체가 아직 없다(`voyage-run-structure-v1.md` §8-5). **자유 배치는 그 화면 위에 3D 커서·접면 하이라이트·미리보기 숫자를 얹는다** — 기항 화면보다 이쪽이 더 크다.
6. **`2`인 이상에서 누가 배치하는가.** `voyage-run-structure-v1.md` §10-4 가 기항 선택에 대해 남긴 미결이 여기서 더 무거워진다. 항목을 고르는 것은 투표로 되지만 **커서를 움직이는 것은 한 명이다.**
7. **결과 화면 정거장 도해가 가변이 된다.** `modular-docking-progression-review-v1.md` §6-6 이 이미 "조립 가능한 부품 그림"이 비싸다고 적었는데, 자유 배치는 그 조합을 사실상 무한으로 만든다. **도해를 그림이 아니라 실제 배의 위에서 본 렌더로 바꾸는 것**을 권고한다 — 그러면 조합 수와 무관해진다. `game-art` 판단.
8. **`RG-1` 문서군의 성격이 바뀐다.** 지금 `rg1-recalc-*` 문서 넷은 "이 배가 통과하는가"를 매번 손으로 재는 기록인데, 자유 배치가 들어오면 배가 매번 다르므로 **손 계산으로는 못 따라간다.** 계산이 코드로 승격되면서 이 문서들은 조문(`rg1-1-measurement-definition-v1.md`)만 남고 나머지는 회귀 테스트로 대체된다. **그건 손실이 아니라 정리다.**

## 11. 단계 제안

**범위를 줄이자는 것이 아니라 검증 순서를 정하는 것이다.** 최종 목표는 §3 의 자유 배치 전부이고, 아래는 그 도중에 무엇을 먼저 세워 무엇을 확인하는지다.

| 단계 | 내용 | 이 단계로 확인하는 것 |
|---|---|---|
| **F0** | 도안 §7-7 사용자 확인 셋 종결. 원반 확정 | 확장부의 기준선(§7-c) |
| **F1** | `Resolve()` 를 사슬 기반으로. 기존 `11`개 구획을 그대로 태워 **결과가 안 바뀌는지** 확인 | §10-1 리스크를 배치 없이 먼저 닫는다 |
| **F2** | `RG-1` 계산을 EditMode 테스트에서 런타임 클래스로 승격. 배치 없이 현재 배 값(`8.21` / `33.2` / `9.81`)을 그대로 재현 | 계산 승격이 값을 안 바꾼다 |
| **F3** | 모듈 프리팹 `2`종(수경재배 · 격납고) + 기항 배치 UI. 미리보기 숫자 셋 | **사례 A·B 가 실제로 일어나는가.** 여기가 재미 판정 지점이다 |
| **F4** | 카탈로그 `6`종 · 루프 허용(F-2) · `RG-1(3)` 개정 | 전면 |

**F3 이 판정 지점이다.** 모듈 두 종류로도 "붙일 자리를 고르는 것이 재미있는가"는 답이 나온다. 재미없으면 F4 의 카탈로그 확장이 그걸 못 고친다.

## 14. 수용 문장

> 기항 화면에서 방 하나를 두 자리에 대 보면 미리보기 숫자가 서로 다르게 뜨고, 플레이어가 그 차이를 보고 자리를 바꾸며, **한도를 넘긴 자리에도 지을 수 있고 지었을 때 실제로 그 구석에서 사람이 죽으면** 이번 방향 PASS.

가운데가 요점이다. 막아 주는 시스템은 자유 배치가 아니고, 결과가 안 따라오는 자유는 배치가 아니라 장식이다.
