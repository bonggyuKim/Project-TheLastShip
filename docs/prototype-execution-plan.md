# LAST SHIFT: 낡은 우주선 — 피벗 프로토타입 실행계획

> 상태: P0 계획 v0.1 · 갱신 2026-08-03 · 정본 기획: `docs/concept-draft.md`

## 0. 목표

첫 프로토타입의 목적은 우주선 전체를 만드는 것이 아니다. **예고된 운석을 맞고 5~7분 안에 추진을 복구해 수동 도킹하는 항해 하나**로 다음 주장을 검증한다. 운석의 궤도·질량·속도는 세 번 모두 고정하고, 시작 상태·자세·물건 배치와 플레이어 대응만 바꾼다.

> **동일한 운석 자극이 현재 선내 상태와 물건 배치에 따라 세 가지 다른 사고·협동 행동으로 이어지고, 2명의 수습 과정이 반복 노동보다 협동과 웃음으로 느껴지는가?**

성공은 무손상이 아니라 `추력 30% 이상, 산소 20% 이상으로 도킹`하는 것이다. 성능·화물·항로 일부를 포기한 생환도 성공으로 인정한다.

사용자가 직접 플레이하고 재미·협동감·웃음을 판정한다. 자동 테스트는 컴파일, 상태 규칙, 리셋, 기본 상호작용 회귀만 확인하며 재미 판정을 대신하지 않는다.

## 1. 운영 원칙

1. 카드 하나는 가능하면 하루 안에 플레이로 확인할 수 있는 크기로 자른다.
2. 구현마다 Editor에 즉시 반영하고 사용자가 직접 플레이한다.
3. 사용자 판정 전에는 완성 아트, 출시 QA, 대규모 증거팩을 붙이지 않는다.
4. 새 기능을 병렬로 넓히지 않는다. 현재 체크포인트가 통과한 뒤 다음 카드를 연다.
5. 기존 드로잉 프로토타입은 실험 결과로 Git에 보존하지만 새 코어의 기술 의존성으로 삼지 않는다.
6. 모든 구현은 정답 아이콘→도구 왕복→게이지 채우기로 수렴하지 않는지 확인한다.
7. 같은 자극의 세 변주가 서로 다른 위치·물건·대화·타이밍을 요구하지 않으면 피벗 코어 실패로 본다.

## 2. P0 수직 슬라이스

### 우주선 회색박스

- 조종 구역
- 중앙 설비·통로
- 생명유지 구역
- 좌현 충돌면과 구역 문

### 최소 상태

- 추진: 점화 가능 여부와 제한 출력
- 전력: 총량과 조향/문/생명유지 배전
- 산소: 구역 압력과 저장량
- 선체: 좌현 충격 내성·파공 여부
- 열: 발전기·엔진 과열 임계치

### 위치가 있는 최소 물건

- 고정 가능한 배터리 1개
- 냉각통과 호스 1세트
- patch plate 1개
- 다목적 손잡이 또는 tether 1개

모든 물건은 위치와 고정 여부가 유지되며 충격으로 움직이고, 잃어버리거나 잘못 연결한 상태가 다음 문제에 영향을 준다.

### 플레이어 행동

- 이동·점프·잡기·놓기
- 물건 전달 또는 던지기
- 케이블 연결
- 설비/물건 붙잡기
- 두 위치 동시 조작
- 짧은 전력 공급과 점화 타이밍
- 구역 문과 압력 제어

## 3. 세 프리셋

운석의 충돌 위치·방향·세기는 동일하게 유지한다. 달라지는 것은 충돌 전 우주선 상태다.

### SP-01A 고열·고추력

- 높은 추력 요구와 엔진 열 상태에서 충격이 냉각 coupling을 이탈시킨다.
- 한 플레이어가 자세와 추력을 낮춰 열 상승을 늦추는 동안 다른 플레이어가 호스를 붙잡고 냉각통을 연결한다.
- 빠른 bypass는 추력을 회복하지만 도킹까지 열 제한을 남긴다.

### SP-01B 전력 과부하·배터리 미고정

- 충격으로 배터리가 이동해 bus 연결을 끊고 조향과 산소 펌프를 함께 약화한다.
- 한 플레이어가 관성 자세를 유지하는 동안 다른 플레이어가 배터리를 붙잡아 고정하거나, 산소를 끄고 조향만 임시 복구한다.
- 성급한 점화는 배터리와 승무원을 다시 날릴 수 있으나 즉시 복구 가능하다.

### SP-01C 나쁜 자세·고압 산소

- 얇은 측면이 충격을 받아 산소관과 선체 결합부에 누출이 생긴다.
- 한 플레이어가 감압 방향과 문을 제어하는 동안 다른 플레이어가 날아가는 patch plate를 잡아 양쪽 latch를 맞춘다.
- 엔진 출력을 포기하면 재가압 전력을 확보할 수 있지만 도킹 성능이 낮아진다.

증명 기준은 세 run의 `첫 지배 문제`, `필수 협동 행동쌍`, `생환 시 포기한 성능`이 모두 다른 것이다. 색과 수치만 다르고 수리 순서가 같으면 변주로 인정하지 않는다.

## 4. 단계와 카드

### SP-00 기획·상호작용 계약 동결

- **소유자:** `game-planning`
- **워크플로:** `game-full`의 기획/스코프 단계
- **산출물:** 상태 전파표, 피해 resolver 입력·출력 계약, 세 프리셋 시작 상태, 구역별 국소 정보, 플레이어 행동 계약, 금지 패턴
- **다음 체크포인트:** PM·사용자가 세 프리셋의 차이와 P0 범위를 승인
- **블로커:** 없음
- **수용 기준:**
  - 동일 운석 입력과 서로 다른 초기 상태가 명시돼 있다.
  - 피해 resolver가 추진·전력·산소·선체·열, 자세, 승무원 위치, 물건 위치·고정 여부와 기존 손상을 입력으로 사용하고 이벤트 이름으로 후속 고장을 직접 호출하지 않는다.
  - 각 프리셋은 서로 다른 협동 행동 2개 이상을 요구한다.
  - 각 프리셋은 `안전 복구 / 빠른 우회 / 성능 포기` 선택과 회복 가능한 실수 경로를 가진다.
  - 구역별 국소 정보와 1초 내 인과 피드백이 정의돼 있다.
  - 반복 입력, 긴 대기, 수리 키트 왕복이 핵심 행동에 없다.
  - P0 제외 범위가 명시돼 있다.

### SP-01 솔로 회색박스·상태 샌드박스

- **소유자:** `game-tech-director`
- **워크플로:** `game-code`
- **산출물:** 작은 우주선 3구역, 플레이어 이동·잡기, 상태 표시, 즉시 프리셋 리셋
- **다음 체크포인트:** 사용자가 혼자 세 프리셋을 전환하며 상태 차이를 확인
- **블로커:** SP-00 승인
- **수용 기준:**
  - 세 프리셋을 5초 이내 리셋·전환할 수 있다.
  - 같은 운석 자극 후 서로 다른 설비·물건 상태가 발생한다.
  - 원인과 결과를 디버그 표시로 읽을 수 있다.
  - 컴파일 오류 0, 핵심 상태 규칙 테스트 통과.
  - 재미 판정은 하지 않고 시뮬레이션 차이만 확인한다.

### SP-02 2인 직접 상호작용

- **소유자:** `game-tech-director`
- **워크플로:** `game-code`
- **산출물:** 로컬 2인 이동·잡기·전달·붙잡기·동시 조작·타이밍 입력
- **다음 체크포인트:** 사용자 포함 2인이 배터리 상황을 플레이
- **블로커:** SP-01 상태 변주 확인
- **수용 기준:**
  - 한 플레이어의 행동이 1초 안에 다른 플레이어의 작업 조건을 바꾼다.
  - 동시 조작은 유일한 정답이 아니라 빠르고 안전한 지름길이며, 1인은 마지막 조종 입력 8초 유지와 임시 고정으로 순차 해결할 수 있다.
  - 배터리 상황에서 두 사람이 동시에 필요한 순간이 존재한다.
  - 2인은 한 사람이 모든 행동을 순차 처리하는 것보다 명확히 빠르고 안전하다.
  - 각 플레이어가 20초 이상 대기하거나 같은 입력을 반복하지 않는다.

### SP-03 세 변주 통합

- **소유자:** `game-tech-director`
- **워크플로:** `game-code`
- **산출물:** SP-01A/B/C를 동일 씬과 공통 상태 규칙으로 플레이 가능하게 통합
- **다음 체크포인트:** 사용자 2인 플레이 3회
- **블로커:** SP-02 협동 동작 확인
- **수용 기준:**
  - 세 프리셋이 서로 다른 위치 이동·물건 사용·타이밍 대화를 요구한다.
  - 고정된 후속 이벤트 스크립트가 아니라 상태 임계치로 결과가 발생한다.
  - 작은 실수마다 즉시 가능한 복구 행동이 있다.
  - 세 프리셋 모두 동일 수리 도구나 게이지 채우기로 수렴하지 않는다.

### SP-04 물리 코미디 조정

- **소유자:** `game-tech-director` / 시각 피드백 자문 `game-art`
- **워크플로:** `game-code`; 재미 통과 뒤 필요한 최소 시각 작업만 별도 `game-art`
- **산출물:** 읽을 수 있는 힘·충돌·물건 이동, 과잉 대응, 복구 가능성 조정
- **다음 체크포인트:** 사용자가 실수 장면의 웃음과 불쾌감을 판정
- **블로커:** SP-03 협동 구조 통과
- **수용 기준:**
  - 의도적인 과잉 대응 3종이 눈에 보이는 결과를 만든다.
  - 첫 실수는 즉사나 긴 재작업으로 이어지지 않는다.
  - 조작 불편이 아니라 상황과 타이밍 때문에 웃음이 발생한다.

### SP-05 P0 사용자 플레이 판정

- **소유자:** `project-manager` 운영 / 사용자 최종 판정
- **지원:** `game-planning` 관찰 기준, `game-qa`는 자동 회귀가 필요할 때만 최소 투입
- **산출물:** 계속 / 1회 수정 / 피벗 판정과 관찰 메모
- **다음 체크포인트:** 다음 마일스톤 결정
- **블로커:** SP-04 플레이 가능 빌드
- **수용 기준:** 아래 Gate P0 기준에 따라 사용자가 직접 결정한다.

## 5. Gate P0 판정

### Continue

다음을 모두 만족한다.

1. 플레이어가 자발적으로 명령·경고·비난·도움을 요청한다.
2. 내 행동이 1초 안에 동료의 화면·몸·작업 조건을 바꾸고, 2인 플레이에서 상대 선택을 항해당 3회 이상 변경한다.
3. 두 플레이어 모두 최소 2구역을 방문한다.
4. 세 프리셋의 첫 지배 문제·필수 협동 행동쌍·생환 절충이 모두 다르다.
5. 실수 하나 이상이 웃음과 즉각적인 추가 수습으로 이어진다.
6. 결과 카드 전에도 두 플레이어가 사고의 인과를 비슷하게 설명한다.
7. 세 번째 run에서 이전과 다른 충돌 전 배치·고정·전력 선택을 자발적으로 한다.
8. 해결 후 “같이 살렸다”는 인상이 남고 다시 항해하고 싶다.

### Revise Once

- 협동 구조는 작동하지만 피드백이 읽히지 않는다.
- 물리 반응은 웃기지만 조작 불쾌감이 섞여 있다.
- 세 프리셋 중 하나만 동일 작업으로 수렴한다.

수정은 하루 이내 한 번으로 제한하고 콘텐츠 추가보다 원인 가독성·상호 영향·복구성을 조정한다.

### Stop / Pivot

- 세 프리셋이 모두 도구 왕복과 게이지 채우기로 수렴한다.
- 20초 이상 대기·반복 입력이 지속된다.
- 각자 독립적으로 일하고 동료 영향이 체감되지 않는다.
- 작은 실수가 즉사나 긴 재작업으로 이어진다.
- 사고를 현재 상태나 플레이어 대응이 아니라 랜덤 탓으로만 이해한다.
- 재도전 의사가 없다.

## 6. P0 이후에만 여는 범위

Gate P0 Continue 이후 다음을 별도 계획한다.

1. 초기 외부 자극 2종 추가
2. 출항·목적지·생환 방식
3. 실제 항해 10~15분 구조
4. 솔로 임시 유지 장치
5. 3~4인 스케일링
6. 외부 우주선·외계인 조우
7. 결과 카드와 인과 사슬 요약
8. 온라인 네트워크
9. 아트 방향·사운드·캐릭터 표현

## 7. 명시적 제외

- 기존 드로잉·잉크·ArmDirect 기능 재사용 의무
- 다수 랜덤 이벤트 카드와 절차 생성 우주
- 전투·포탑·적 AI·복수 운석·다수 사건 덱
- EVA·외계 생물·외부 수급
- 캠페인·대사극·로그라이트 성장
- 제작·인벤토리·연료 경제·AI 승무원
- 완성 UI·아트·VFX·사운드
- 온라인·매칭·저장
- 3~4인 구현
- 출시 수준 QA·대규모 계측·증거팩
- 현실적인 궤도·유체·부품 시뮬레이션

## 8. 의존성

```text
SP-00 기획 계약
  → SP-01 솔로 상태 샌드박스
    → SP-02 2인 직접 상호작용
      → SP-03 세 변주 통합
        → SP-04 물리 코미디 조정
          → SP-05 사용자 플레이 판정
            → Continue일 때만 항해·콘텐츠·3~4인 확장
```

한 번에 준비됨으로 둘 카드는 `SP-00` 하나뿐이다. 이후 카드는 앞 체크포인트 통과 전까지 백로그에 둔다.
